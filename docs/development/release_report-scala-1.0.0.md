## 4 つの問いへの答え

[第 13 章](../article/zettai/scala/chapter13.md) に書いた答えの要約です。

1. **核と殻の分離は型で守られたか。** 一部だけ。`IO` を返す関数と返さない関数は型で区別できたが、`IO` を使わない副作用（`println`、例外）は型で止められなかった。分離は、ドメインに `cats.effect` を取り込まない規律と、ログを外から包む設計で守った
2. **自作した抽象は、Cats のものと何が違ったか。** `Monoid`・`Functor`・`Validated`・`Profunctor` は Cats と突き合わせた。Cats の `Endo` は合成の向きが逆だった。置き換えられるものが多かったが、向きの違いを閉じ込める自作と、ライブラリに無い JSON・ログは残した
3. **`IO` の遅延評価は、テストをどう変えたか。** テストが `IO` を返し、実行前後の回数や、時計・出力先の差し替えを書けるようになった
4. **`Resource` は、後始末を保証したか。** サーバー、クライアント、テスト用のテーブルでは保証した。`lazy val` で起動した Testcontainers には及ばなかった

1 つの題材、1 つの実装、Scala 3.3.9 と Cats Effect 3.7.1 での観察です。一般論の根拠はありません。

## 失敗と、その直し方

**CI は Scala の push で一度も落ちませんでした。** Flix 版で記事のコードと実装がずれて CI が落ちた経験を踏まえ、push の前に記事の検査を回しました。ずれた記事のコード（第 2・4・6・7・8 章）には、当時のコミットを添えた `code-check: ignore` を付けました。

**コミットの混入が二度ありました。** 第 8 章の記事を、版を持たせた実装のコミット（`a3a8a9a`）に入れてしまいました。ADR-050 の承認を、第 8 章の実装のコミット（`98db184`）に入れてしまいました。どちらも push 済みで、作り直していません。コミットメッセージに記録しました。

## 学び

- **宣言した範囲だけを、言う。** Cucumber、circe、log4cats を「試していない」と書いたので、ADR に比べた結果の無い主張が残らなかった
- **壊してみる。** 法則のテストは、通るだけでは何も言えない。壊れた実装を見分けることを、毎回示した
- **コンパイラが守らない境界を、往復のテストで守る。** 文字列で `match` する読み戻しは、`enum` の網羅性の検査が及ばなかった
- **ログは観測にもなる。** 保管場所の記録の並びが、二重の読み出しを見つけた
- **push の前に検査を回す。** 記事のコードと実装のずれは、CI の前にローカルで見つけられる
