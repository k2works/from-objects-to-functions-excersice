# 第 8 章 ファンクタを使ってイベントを射影する

第 5 章で、イベントを畳み込んで `ToDoList` を作りました。

**同じイベントから、別の形も作れます。** 一覧に出したいのは「リスト名と件数」だけで、項目の中身は要りません。

## イベントを射影する

クエリのための型を作ります。

```rust
pub struct ListSummary {
    pub list_name: String,
    pub item_count: usize,
}
```

**項目の中身を持ちません。** 一覧を出すのに全部を読み込まなくてよくなります。

作り方は第 5 章とまったく同じです。イベント 1 つを「状態から状態への関数」にして、畳み込みます。

```rust
pub fn summary_transform_for(event: ToDoListEvent) -> SummaryTransform {
    match event {
        ToDoListEvent::ListCreated { list_name } => Box::new(move |_previous| ListSummary {
            list_name: list_name.0.clone(),
            item_count: 0,
        }),
        ToDoListEvent::ItemAdded { .. } => Box::new(|summary| ListSummary {
            item_count: summary.item_count + 1,
            ..summary
        }),
    }
}
```

**`ItemAdded` が項目の中身を見ていません。** 数えるだけです。同じイベントでも、**射影先が違えば見るところが違います**。

第 5 章で `Box<dyn Fn>` に揃えた形（[ADR-030](../../../adr/ADR-030-functional-di-shape.md)）が、そのまま 2 つめの射影でも使えました。**書き方を考え直す必要がありませんでした。**

## ファンクタに対するクエリの実行

一覧を返す入れ物に `map` を持たせます。

```rust
    pub fn map(self, f: impl Fn(ListSummary) -> ListSummary) -> Summaries {
        Summaries(self.0.into_iter().map(f).collect())
    }
```

**中身は `Iterator::map` に任せています。** 書いているのは「包み直す」ところだけです。

| 対象 | この節で書いたもの |
| :--- | :--- |
| Kotlin | `Functor` を自作した |
| なでしこ3 | `射影写像` を書いた |
| **Rust** | **包み直すだけ。中身は言語にある** |

第 7 章と同じ形です。**言語が与えるほど、書くものが減ります。**

## ファンクタの観点から考察する

法則を確かめます。第 7 章では `Result` で確かめました。**今度は別の入れ物です。**

ファンクタの主張は「**入れ物が変わっても法則は同じ**」なので、**2 つ確かめて初めて主張が立ちます**。1 つでは、その入れ物の性質かもしれません。

### つまずき: 検出率が 1.8σ ずれた

例によって壊して数えます。**件数がちょうど 2 のときだけ変換を飛ばす**ようにしました。

```text
隠れた欠陥の検出 61 / 200
```

計算はこうです。

```text
p = P(件数 == 2) = 1/4 = 0.25
期待値 = 200 × 0.25 = 50
σ = √(200 × 0.25 × 0.75) = 6.12
```

**61 は期待値から 1.8σ 上です。** 第 7 章では 50 / 200 でぴったり一致していたので、**生成器が偏っているのではないか**と疑いました。

種を 20 通り変えて数え直しました。

```text
20 種の「件数 2」の回数: [55, 52, 38, 53, 47, 46, 40, 49, 58, 53, 47, 61, 59, 61, 49, 37, 49, 50, 56, 42]
平均 50.1（理論 50）
```

**偏っていませんでした。** この種でたまたま上に出ただけです。

**これがしきい値に 4σ 取ってある理由です。** 1.8σ は 20 回まわせば何度か出ます。なでしこ3 版はしきい値を 1.58σ に置いて、**CI が確率 5.7% で落ちていました**。

疑って確かめたのは無駄ではありませんでした。**「ずれた」と「間違っている」は別物で、区別するには数え直すしかありません。**

## コマンドクエリ責務分離 (CQRS)

コマンド側とクエリ側で、変換の型が違います。

```text
コマンド側: Box<dyn Fn(ToDoList) -> ToDoList>
クエリ側:   Box<dyn Fn(ListSummary) -> ListSummary>
```

**混ぜると止まります。** わざと書いて確かめました。

```text
error[E0308]: mismatched types
   expected `Box<dyn Fn(ListSummary) -> ListSummary>`,
      found `Box<dyn Fn(ToDoList) -> ToDoList>`
```

2 対象はここを**約束で守りました**。命名（`コマンド〜` / `クエリ〜`）と置き場所で分け、混ぜても動いてしまいます。

これは第 3 章の境界と同じ構図です。**2 対象が検査や約束で守ったものを、型が肩代わりします。**

ただし第 6 章で見たように、**型が守る範囲には境目があります**。ここで守られているのは「違う型を渡さない」ことだけで、「**クエリ側でコマンドを実行しない**」ことは守られていません。それは呼ぶ側の書き方の問題で、型には現れません。

| 何を守るか | 守るもの |
| :--- | :--- |
| 違う型の変換を渡さない | **コンパイラ** |
| クエリ側から状態を変えない | **書く人** |

## まとめ

- **同じイベントから別の形を作りました。** 射影先が違えば、同じイベントでも見るところが違います
- **第 5 章の形（`Box<dyn Fn>` に揃える）がそのまま使えました。** 2 つめの射影で書き方を考え直す必要がありませんでした
- **`map` は包み直すだけでした。** 中身は `Iterator::map` です。Kotlin 版は `Functor` を自作しました
- **ファンクタ則を 2 つめの入れ物で確かめました。** 「入れ物が変わっても同じ」が主張なので、1 つでは足りません
- **検出率が 1.8σ ずれ、生成器を疑って数え直しました。** 種 20 通りの平均は 50.1 で、偏りではありませんでした。**「ずれた」と「間違っている」は別物です**
- **CQRS の境界を型が守りました。** 2 対象は約束で守っています
- **ただし守る範囲には境目があります。** 「違う型を渡さない」は守られ、「クエリ側から状態を変えない」は守られません

次の章で永続化します。**`async` を採らなかった判断が、そこで試されます。**
