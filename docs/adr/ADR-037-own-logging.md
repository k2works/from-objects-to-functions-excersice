# ADR-037 記録と JSON を自前で書き、tracing と serde を入れない

日付: 2026-09-29

## ステータス

2026-09-29 提案されました

## コンテキスト

第 12 章で構造化ログと双方向変換を書きます。要求は 2 つです。

1. **書き出しと読み込みが 1 つになっている**（プロファンクタ）
2. 記録が構造を持ち、**出力先を差し替えられる**

[ADR-032](ADR-032-postgres-event-store.md) にこう書きました。

> **1 件の代償では判断が決まりません。** 第 12 章でログの JSON が要るとき、もう一度測ります。**自前のパーサが 3 か所に増えていたら判断を変えます**

### 数えた

**自前で文字列を解く箇所は 3 種類ありました。**

| # | 何を解くか | 場所 | 足した章 |
| :--- | :--- | :--- | :--- |
| 1 | JSON | `event_store.rs` | 9 |
| 2 | フォーム | `http.rs` | 11 |
| 3 | HTML（テスト用） | `acceptance.rs` | 3・11 |

**ただし条件の書き方が曖昧でした。** 「自前のパーサ」が JSON だけを指すなら 1 か所です。**条件を書いたときに数え方を決めていません。**

### 測った

条件を先に決めました（空のクレートから、`cargo add` → `cargo clean` → build、各案とも同じ手順）。

| | 自前 | `serde_json` のみ | `serde`(derive) + `serde_json` | `tracing` | `tracing` + `subscriber` |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 依存クレート | **+0** | +5 | **+11** | +9 | **+18** |
| ビルド | **0 秒** | 9.86 秒 | 14.48 秒 | 11.19 秒 | **15.23 秒** |

### 要求を既定で満たすか — **満たしました**

```text
serde: {"ItemAdded":{"item":"読む 本&\"<x>\""}}
tracing: {"timestamp":"...","fields":{"message":"追記した","user":"uberto","appended":2},...}
```

`serde` の derive は**1 つの宣言から両方向を作る**ので、綴りがずれようがありません。`tracing` は構造を持つ記録を出し、**出力先も差し替えられました**（テストで実測）。

**`serde_json` だけでは満たしません。** 書き側と読み側が別のコードのままです。

## 決定

**両方とも自前で書きます。**

1. 記録は `Record`（何が起きたか + キーと値の並び）と `LogSink`（行き先）で表す
2. 書き出しと読み込みを `Converter<A, B>` に**1 つにまとめる**（プロファンクタ）
3. 記録の JSON も自前。第 9 章と同じ判断
4. **ドメインは記録の手段を知らない。** クレートの境界が守る（[ADR-027](ADR-027-crate-boundary.md)）

### 要求を満たしていたのに入れなかった理由

**第 11 章で `tera` を入れたときと、判断の形が違います。**

| 章 | 既製品 | 要求を満たすか | 判断 | 決め手 |
| :--- | :--- | :--- | :--- | :--- |
| 11 | `tera` | **満たす** | **入れた** | 自作する理由が消えた |
| **12** | **`serde` derive** | **満たす** | **入れない** | **[ADR-027](ADR-027-crate-boundary.md) が壊れる** |
| **12** | **`tracing`** | **満たす** | **入れない** | **+18 クレート・+15.23 秒。`just check` の余裕が 4 秒弱** |

**`serde` の derive は属性を `ToDoListEvent` に書く必要があります。** その型はドメインのクレートにあり、**第 3 章から依存 0 を守ってきました**。これは**境界検査を 1 行も書かずに済んだ根拠**です。

鏡の型を HTTP 側に置く手はありますが、**ドメインとの写しを手で書く**ことになり、対であることの利点がそこで失われます。

**`tracing` は数字が合いません。** `tera` は +3・18.42 秒でした。**同じ「要求を満たす」でも、払う額が違います。**

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `serde` derive をドメインに入れる | **[ADR-027](ADR-027-crate-boundary.md) が壊れる。** 12 章通しで守った性質を最終 Unit で崩すことになる |
| 鏡の型を HTTP 側に置く | **写しを手で書くので、対であることの利点が写しの部分で失われる。** 依存 +11 の対価に見合わない |
| `serde_json` だけ入れる | **要求を満たさないのに依存が増える。** 書き側と読み側が別のまま |
| `tracing` を入れる | **+18 クレート・+15.23 秒。** `just check` の余裕が 4 秒弱しかない |

## 影響

- **ドメインのクレートは最後まで依存 0 です。** 第 3 章から第 13 章まで通しました
- `Converter<A, B>` で**片方だけ直す形が書けなくなりました**。第 9 章で `jsonb` の正規化に対応したとき、**読み側だけを直しています**
- 記録の行き先を差し替えられます（`Silent` / `ToStdout` / テスト用）
- **clippy に `type_complexity` で 3 回目に止められました**（`Write<A, B>` / `Read<A, B>` と名前を付けた）

### つまずき: 記録を足す場所が、境界を入れたことで変わっていた

`EventStore` の `append` / `events_of` に記録を足して、**1 件も出ませんでした**。

第 10 章で境界を入れてから、実際の読み書きは **単位の中の口**（`TxEventStore` の実装）を通ります。**`PgTx` に持たせる必要がありました。**

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **記録の水準（レベル）** | いまは全部同じです。`tracing` を入れれば既定で付きますが、**この連載では絞り込みを扱いません** |
| 記録の時刻 | 付けていません。**行き先が付ける前提**です |
| 記録の量 | 保管の読み書きだけです。**コマンドの処理そのものは記録していません** |
| 自前の JSON をいつまで続けるか | **第 12 章で条件を測り直しました。** 条件の書き方（数え方）が曖昧だったことも含め、**連載としてはここで打ち止め**です |

## コンプライアンス

- ドメインの `Cargo.toml` に `serde` / `tracing` が現れないこと
- ドメインのコードに記録の実体（ファイル・標準出力）が現れないこと
- **書き出しと読み込みが `Converter` を通ること**（別々の関数で呼ばれていないこと）
