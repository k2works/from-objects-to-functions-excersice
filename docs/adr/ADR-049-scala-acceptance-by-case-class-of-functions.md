# ADR-049 Scala 版は受け入れテストの経路を関数値のケースクラスで差し替え、Cucumber を入れない

日付: 2026-11-02

## ステータス

提案（人の承認待ち）

## コンテキスト

第 3 章で受け入れテストを抽象化します。同じシナリオを複数の経路で走らせ、片方だけ落ちたらそこに業務のロジックが漏れている、と判断する形です（[ADR-028](ADR-028-own-acceptance-trait.md)、[ADR-046](ADR-046-flix-acceptance-by-record-of-functions.md)）。

既存の対象の手段は次のとおりです。

| 対象 | 手段 |
| :--- | :--- |
| Kotlin | Pesticide の `DdtActions` |
| Kotlin FP | Gherkin と Cucumber |
| なでしこ3 | 関数値を詰めた辞書 |
| Rust | トレイト |
| Flix | 関数値のレコード |

Scala 版の執筆計画（[outline.md](../article/outline.md)）では、Cucumber を使えるかを確認する事実 ⑦ に挙げていました。

### 確かめたこと、確かめていないこと

| 項目 | 状態 |
| :--- | :--- |
| `cucumber-scala_3` が存在すること | **確認済み。** Maven Central に 9.2.1 がある（2026-11-02 に確認） |
| Cucumber を Scala 3.3.9 と munit-cats-effect の `IO` と組み合わせて動かすこと | **試していない。** step definitions が `IO` を返せるか、`CatsEffectSuite` と同じランナーで走るかは未確認 |
| 関数値を持つケースクラスで経路を差し替えること | **確認済み。** 第 3 章で `domain` と `http` の 2 経路を同じシナリオで実行した |

つまり、**Cucumber が使えないと確かめたわけではありません。** 存在は確かめたうえで、試さずに採らない、という判断です。

## 決定

**関数値を持つケースクラス `ZettaiActions` で経路を差し替えます。Cucumber を入れません。**

1. シナリオが使う操作を、関数値を持つケースクラスに並べる
2. 経路ごとに `Resource[IO, ZettaiActions]` を作る（`domainActions` / `httpActions`）
3. シナリオは `ZettaiActions` を受け取り、どの経路か知らない
4. `name` を失敗メッセージに含め、どの経路で落ちたかが分かるようにする

### 採った理由

- **必要なのは経路の差し替えで、Gherkin ではない。** シナリオは業務の言葉だけの関数として書ける
- **追加の依存が要らない。** MUnit と Cats Effect の `Resource` だけで足りる
- **`Resource` で後始末が型に載る。** HTTP 経路のサーバーとクライアントは、シナリオを抜けると必ず止まる
- **試すコストが高く、得るものが小さい。** 得られるのは `.feature` ファイルによる一覧性だけ

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `cucumber-scala_3` を使う | `IO` との組み合わせが未確認。依存とランナーが増える。得るものは一覧性だけ |
| 型クラスで経路を表す（`trait Actions[F[_]]`） | 経路が 2 つの段階では抽象が過剰。第 4 章の関数型 DI で方式を比べるときに再検討する |
| 経路ごとにテストを複製する | シナリオが増えるたびに経路の数だけ複製することになる |

## 影響

- 依存もビルド時間も増えない
- シナリオは経路を知らない。経路を足すとき、シナリオは変わらない
- HTML の生成で項目の順序を壊すと、失敗メッセージに `"http"` と経路名が出て、`domain` は通る（第 3 章）

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| 非エンジニアがシナリオを読み書きすること | Gherkin を入れればできるが、この連載の読者は開発者。必要になったら入れ直す |
| シナリオの一覧性 | `.feature` のような一覧はない。テストの名前が代わりになる |
| Cucumber が使えるかどうかの確認 | 未確認のまま残る。使えると分かった場合も、この決定は覆さないが、記事の記述は直す |
| 経路が増えたときの組み合わせ | 第 9 章で永続化の経路が入る見込み。そのときに重みを測る |

## コンプライアンス

- シナリオが具体的な経路（`domainActions` / `httpActions`）を名指ししないこと
- 経路を足したとき、シナリオのコードが変わらないこと
- 失敗メッセージに経路の名前が入ること
