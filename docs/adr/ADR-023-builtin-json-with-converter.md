# ADR-023 組み込みの JSON を使い、その上に双方向変換を置く

日付: 2026-09-28

## ステータス

2026-09-28 提案されました

## コンテキスト

Kotlin 版は [ADR-012](ADR-012-own-json-converter.md) で、Kondor を導入せず、手書きのシリアライズを双方向変換の型（`Converter`）に発展させました。

**なでしこ3 版は前提が違います。** 第 9 章の時点から、組み込みの `JSONエンコード` / `JSONデコード` を使っています（`store.nako3`）。JSON を作る処理を自前で書いてはいません。

Unit 6 のふりかえり Try 5 は「**『自前で書く』を惰性で続けない**」でした。既にあるものを捨てて自前で書く理由があるかを、先に確かめる必要がありました。

### 組み込みで足りていること・足りていないこと

スパイクで確かめました。

| 確かめたこと | 結果 |
| :--- | :--- |
| 入れ子の辞書・配列の往復 | できる。再エンコードした文字列も一致する |
| キーの順序 | 挿入順を保つ |
| 壊れた入力 | **例外を投げる**（空を返さない） |

**JSON そのものは足りています。** 足りていないのは 1 点だけです。

**書き出しと読み込みが別々の関数だと、片方だけ直して壊せます。** 第 11 章で `ListRenamed` を足したとき、`store.nako3` の書き出しと読み込みの両方を直す必要がありました。忘れたら往復が壊れます。これは Kotlin 版 ADR-012 が挙げた問題とまったく同じ形です。

## 決定

**JSON の生成は組み込みに任せ、その上に「書き出しと読み込みを対にする層」だけを自前で置きます。**

1. `converter.nako3` に、書き出しと読み込みを 1 つの辞書に入れた**双方向変換**を置く
2. 出力側は `変換出力写像`（map）、入力側は `変換入力写像`（contramap）で変えられる。両方を持つのでプロファンクタ
3. `JSONデコード` の例外は、**境界の 1 か所（`事象読込`）で `エラー監視` で捕まえ**、第 7 章の結果に変える
4. 保管（`store.nako3`）は行の形を自分で決めず、変換に委ねる
5. 変換は**純粋**にする。中で入出力をしない

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| Kotlin 版と同じく JSON の生成から自前で書く | 組み込みで足りている。**「自前で書く」を惰性で続けない**（Unit 6 Try 5）。連載の主題は「言語が与えないものを自分で組む」ことで、与えられているものを組み直すことではない |
| 組み込みをそのまま使い、変換の層を置かない | 第 9 章の形のまま。書き出しと読み込みが別々で、片方だけ直して壊せる。第 11 章で実際にその危険を踏んだ |
| 例外をそのまま上へ投げる | 第 7 章で「例外をやめて結果辞書にする」と決めている。境界で変えるほうが一貫する |
| 変換に入出力を持たせる（ファイルまで書く） | **関数値ごしに呼べなくなる**（既知の制約 1）。第 12 章で実際に踏んだ（下記） |

## 影響

- **片方だけ直して壊すことができなくなります。** 書き出しと読み込みが 1 つの辞書に入っています
- 行の形を変えたいときに触る場所が 1 か所になります
- 壊れた行を読んでも落ちません。失敗として返り、記録に残ります
- プロファンクタという 7 つめの代数構造が、既にある道具（性質テストと検出率）でそのまま扱えます

### 記録を足して踏んだこと

最初、記録（ログ）を `保管読出` の中に入れました。**受け入れテストが落ちました。**

読み出しを関数値ごしに呼ぶ経路があり、中に書き出し（非同期）が入った瞬間に Promise が返るようになったためです（既知の制約 1 の **5 度目**）。

**関数値ごしに呼べるかどうかは「中で何を呼ぶか」で決まります。** 既存の関数に書き出しを足すと、それまで注入できていた経路が壊れます。記録は呼び出し側（`tx.nako3`）へ移しました。

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **スキーマの検証** | 読み込んだ辞書にどのキーがあるかは確かめません。第 7 章から、辞書のキーの約束は契約テストが守っています |
| **版の管理** | 行の形が変わったときに古い行をどう読むかは決めていません。[ADR-019](ADR-019-file-event-log.md) で解かないことに挙げた後方互換のままです |
| **組み込みの JSON の挙動** | キーの順序や数値の表し方は処理系に依存します。比較は `比較用文字列`（JSON 化してから文字列で比べる）に頼っており、処理系が変われば崩れます |

## コンプライアンス

- 保管の行の形を `store.nako3` が直接決めないこと（変換を通すこと）
- `JSONデコード` を呼ぶ場所が `converter.nako3` の 1 か所だけであること
- 変換が入出力をしないこと（純粋であること）
