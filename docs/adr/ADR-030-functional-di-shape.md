# ADR-030 関数型 DI は impl Fn、並びに入れる変換は Box<dyn Fn> にする

日付: 2026-09-29

## ステータス

2026-09-29 提案されました

## コンテキスト

第 4 章で関数型の「依存性の注入」を入れます。**依存をインターフェースではなく関数値として渡す**形で、3 対象に共通の主題です。

| 対象 | 依存の持ち方 |
| :--- | :--- |
| Kotlin | 関数型（`(User, ListName) -> ToDoList?`）を引数に取る |
| なでしこ3 | 関数値を詰めた辞書（型が無いので、詰めるだけ） |
| **Rust** | **3 通り書ける** |

Rust の 3 案は次です。

- **案 A**: `impl Fn` を引数・型引数で受ける（静的ディスパッチ）
- **案 B**: `Box<dyn Fn>` を持つ（動的ディスパッチ）
- **案 C**: 自前のトレイトとジェネリック型パラメータ

### 第 5 章まで書いてから比べた

第 4 章だけを見て決めると、第 5 章（イベントの畳み込みとモノイド）で書き直しになります。そこで **3 案それぞれで「状態から状態への関数を合成して畳み込む」ところまで書きました**（`apps/rust/zettai/spikes/di-shapes/`）。

| | 案 A `impl Fn` | 案 B `Box<dyn Fn>` | 案 C トレイト |
| :--- | :--- | :--- | :--- |
| 依存を差し替える（第 4 章） | できる | できる | できる |
| 2 つの変換を合成する | できる | できる | できる |
| **長さが実行時に決まる列を畳み込む（第 5 章）** | **できない** | **できる** | **できない** |
| ディスパッチ | 静的 | 動的 | 静的 |
| `just check` | 差無し | 差無し | 差無し |

**第 4 章だけを見ていたら 3 案とも通っていました。**

案 A が落ちるのは、`impl Fn` が**書くたびに別の型になる**ためです。

```text
= note: expected opaque type `impl Fn(Vec<String>) -> Vec<String>`
           found opaque type `impl Fn(Vec<String>) -> Vec<String>`
= note: distinct uses of `impl Trait` result in different opaque types
```

案 C が落ちるのは、合成の結果が別の型になるためです。`fold` の 1 周目で `Identity` が `Composed<Identity, Add>` になり、2 周目で型が合いません。

**案 B だけが、合成しても型が変わりません。** 単位元から始めて合成を繰り返せます。

## 決定

**使い分けます。**

1. **差し替えるだけの依存は `impl Fn`（型引数）で受ける**。`ToDoListHub<F, S>` がその形
2. **並びに入れて畳み込む変換は `Box<dyn Fn>` に揃える**（第 5 章のイベント）
3. `Box<dyn Fn>` を構造体のフィールドに直接書かず、**型別名を付ける**（clippy の `type_complexity`。付けたほうが記事でも指せる）
4. クロージャに閉じ込める値は**借りずに所有する**。`Box<dyn Fn>` は既定で `+ 'static`

### 判断の基準

**「その関数値は、他の関数値と同じ入れ物に入るか」**で決めます。

| 入るか | 形 |
| :--- | :--- |
| 入らない（配線のときに 1 つ決まるだけ） | `impl Fn` |
| 入る（`Vec` に並べる、`fold` で畳む） | `Box<dyn Fn>` |

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| すべて `Box<dyn Fn>` に統一する | 読みやすいが、**配線のためだけに動的ディスパッチを払う**。使い分けの理由そのものが章の主題になるので、統一すると書くことが無くなる |
| すべて `impl Fn` に統一する | **第 5 章で書けない** |
| 案 C（トレイトで表す） | 同上。加えて、関数 1 つのためにトレイトと構造体を書くことになる |

## 影響

- **第 4 章と第 5 章で関数値の形が変わります。** なぜ変わるかを説明する必要があり、それがこの 2 章の主題になります
- 配線（`ToDoListHub::new`）が静的なので、**呼び出しがどのクロージャに解決されたかがバックトレースに出ます**（`run::<...{closure#1}>`）。`Box<dyn Fn>` では出ません
- 型引数が構造体に付くので、**ハブを構造体のフィールドに持つときは型を書けません**。`fn hub(&self) -> ToDoListHub<impl Fn.., impl Fn..>` のように、その場で組み立てます
- ジェネリクスの単相化でコードが増えます。**いまの規模では測れる差はありません**

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **依存が 3 つ以上になったとき** | いまは `fetch` と `save` の 2 つです。増えたら型引数も増えます。**5 つを超えたら構造体にまとめるかを判断します** |
| ハブを長く持ち回るとき | 型引数のせいで構造体のフィールドに持てません。いまは呼ぶたびに組み立てています。**第 9 章で永続化が入ったときに見直します** |
| `FnMut` が要るとき | 保存先は `&self` のまま書き換えるために `Mutex` を使っています。**`FnMut` にすると並びに入れられなくなる**ので、避けています |
| 非同期の依存 | [ADR-024](ADR-024-no-async.md) で async を採らないと決めています |

## コンプライアンス

- `Box<dyn Fn>` が構造体のフィールドに直接書かれていないこと（型別名を経由する）
- ドメインのクレートが、依存の実体（保存先）を知らないこと
- 第 5 章の変換が `Box<dyn Fn>` に揃っていること
