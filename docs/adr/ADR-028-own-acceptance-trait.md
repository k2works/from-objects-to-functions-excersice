# ADR-028 受け入れテストの経路をトレイトで差し替え、cucumber を入れない

日付: 2026-09-29

## ステータス

2026-09-29 提案されました

## コンテキスト

第 3 章で受け入れテストを抽象化します。**同じシナリオを複数の経路で走らせ、片方だけ落ちたらそこに業務のロジックが漏れている**と判断する形です（[ADR-016](ADR-016-own-acceptance-entry.md)）。

2 対象の手段はこうでした。

| 対象 | 手段 |
| :--- | :--- |
| Kotlin | Pesticide の `DdtActions`（ライブラリ） |
| なでしこ3 | 関数値を詰めた辞書（自作。[ADR-016](ADR-016-own-acceptance-entry.md)） |

**Rust では既製品を先に調べます。** 全 Bolt 共通のゲート項目であり、なでしこ3 版 Unit 7 の Try 5（「自前で書く」を惰性で続けない）でもあります。

### 実測した

`cucumber` 0.23.0 を入れて測りました。

| 項目 | 現状 | `cucumber` を入れると |
| :--- | :--- | :--- |
| 依存クレート数 | **6** | **127** |
| ビルド時間 | — | **+92 秒** |

**`just check` の上限は 20 秒**です（[ADR-026](ADR-026-just-and-coverage.md)）。単独で超えます。

与えてくれるのは Gherkin の `.feature` ファイル、つまり**自然言語でシナリオを書く仕組み**です。

**しかし、連載が必要としているのはそれではありません。** 必要なのは「経路の差し替え」で、シナリオ自体は第 2 章の時点で既に業務の言葉だけで書けています。

## 決定

**トレイトで経路を差し替えます。`cucumber` を入れません。**

1. `ZettaiActions` トレイトに、シナリオが使う操作を並べる
2. 経路ごとに実装する（`DomainOnly` / `ThroughHttp`）
3. シナリオは `&dyn ZettaiActions` を受け取り、**どの経路か知らない**
4. `route()` で経路の名前を返す。**どの経路で落ちたかが分かる**

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `cucumber` を入れる | 依存が 6 → 127、ビルドが +92 秒で `just check` の上限を単独で超える。**与えるのは Gherkin で、必要なのは経路の差し替え** |
| 関数値の構造体（なでしこ3 版の踏襲） | Rust ではトレイトのほうが素直。**踏襲を惰性でしない**（Unit 1 Try 3） |
| ジェネリクス（`fn scenarios<A: ZettaiActions>(a: &A)`） | 経路を `Vec` に入れて回せない。**全経路を 1 つのテストで回す**形にしたかった |
| 経路ごとにテスト関数を複製する | シナリオが増えるたびに経路の数だけ複製することになる |

## 影響

- **依存もビルド時間も増えません。** トレイトは言語にあります
- シナリオが経路を知りません。経路を足すときシナリオは変わりません
- **`route()` があるので、どの経路で落ちたかがメッセージに出ます。** なでしこ3 版 Unit 6 で `/rename` 以外への POST の欠陥を捕まえたのは、経路名が出ていたからです
- **HTTP 経由の経路でサーバを起こしません。** `handle` が `tiny_http` の型を返さないためです（第 2 章）。なでしこ3 版は `Makefile` が起動と停止を持つ必要がありました

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **非エンジニアがシナリオを読み書きすること** | Gherkin を入れればできますが、この連載の読者は開発者です。**必要になったら入れ直します** |
| **シナリオの一覧性** | `.feature` ファイルのような一覧はありません。テスト関数の名前が代わりになります |
| **`Box<dyn>` の実行時コスト** | 動的ディスパッチになります。受け入れテストなので問題にしません |
| **経路が増えたときの組み合わせ** | 第 9 章で永続化経由の 3 経路目が入る見込みです。**経路 × シナリオが増えることの重みは、そのとき測ります** |

## コンプライアンス

- シナリオが具体的な経路（`DomainOnly` / `ThroughHttp`）を名指ししないこと
- 経路を足したとき、シナリオのコードが変わらないこと
- 失敗メッセージに経路の名前が入ること
