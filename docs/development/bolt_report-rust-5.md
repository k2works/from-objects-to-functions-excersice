## 判断と学び

### 1. ゲートが 2 / 2 で同期停止した

**累計 11 / 11（100%）**です。なでしこ3 版の 41 箇所中 1 回に対し、ここまで **11 箇所中 11 回**です。

| ゲート | 添えた数字 | 決定 |
| :--- | :--- | :--- |
| 段階の切り方 | 3 案 × 初回・定常の秒数 + **過去段階が壊れたら気づくか** | **このまま切り続ける** |
| DB を検査に含めるか | 3 案 × CI とローカルの秒数（**使い捨てブランチで実測**） | **別ジョブに分ける** |

**ゲート 2 では「速さ」以外の軸が決め手になりました。** 古い段階を workspace から外す案は 3〜5 秒速いのですが、**過去段階が壊れても気づかなくなります**（わざと壊して確認）。記事が指すコードが腐るので採りませんでした。

### 2. `async` を採らなかった判断は持ちこたえた

[ADR-024](../adr/ADR-024-no-async.md) は Unit 1 の後戻りの効かない判断でした。**第 9 章で試され、持ちこたえました。**

`INSERT`・`SELECT`・トランザクションのすべてが同期で書け、**`async fn` が第 1〜8 章に伝播しませんでした**。

ただし記事には「**持ちこたえたの中身は『困らなかった』であって『同期のほうが良かった』ではない**」と書いています。1 プロセスで 1 リクエストずつ扱う規模だから困らなかっただけです。

### 3. 自前の JSON が、判断の代償をすぐに払った

`serde_json`（依存 +5・ビルド +8.30 秒）を入れず自前で書きました（[ADR-012](../adr/ADR-012-own-json-converter.md) を踏襲）。

**`jsonb` は正規化して返します。** コロンの後ろに空白が入り、自前のパーサが読めませんでした。

**単体の往復テストは通っていました。** 自分で書いた文字列を自分で読み返していたためです。**DB を通す結合テストだけが見つけました。**

記事には「**1 件の代償では判断が決まらない。第 12 章で測り直す**」と書いています。自前のパーサが 3 か所に増えていたら判断を変えます。

### 4. CI の見積もりを実測が訂正した

ゲート 1 で「**別ジョブなら並走するので総時間は増えない**」と説明しました。**CI 全体については間違いでした。**

| ジョブ | 前 | 後 |
| :--- | :--- | :--- |
| `fmt, clippy, test, coverage` | 26 秒 | **56 秒** |
| 保管との往復 | — | 51 秒 |
| `parity` | 6 秒 | 5 秒 |

**`check` が 30 秒遅くなりました。** サービスコンテナではなく、`postgres` クレートの**コンパイル**です。`cargo test --all` はテストを走らせなくても依存をビルドします。**フィーチャで隠せるのはテストの実行だけです。**

どの案を選んでも同じ 30 秒は乗るので、**判断自体は正しいまま**です（含めた場合の見込み 78 秒に対し、実測 56 秒）。記事と [ADR-033](../adr/ADR-033-db-check-as-separate-job.md) の両方を実測に合わせて直しました。

### 5. 同じ ADR の題材で、Kotlin 版と結論が分かれた

[ADR-009](../adr/ADR-009-integration-test-database.md) は「結合テストを `check` に含める。別ジョブに分けない」です。**Rust 版は分けました。**

| 対象 | `check` の所要 | +22 秒すると |
| :--- | :--- | :--- |
| Kotlin | 95 秒 | 117 秒（+23%） |
| **Rust** | **26 秒** | **48 秒（+85%）** |

**同じ題材でも、数字が違えば結論が変わります。** 第 3 章第 5 節（3 対象で結論が 3 通り）に続く 2 例目です。

### 6. 検出率の揺れを 2 回測った

| 章 | 実測 / 期待値 | ずれ |
| :--- | :--- | :--- |
| 第 8 章（射影のファンクタ） | 61 / 50 | **+1.8σ** |
| 第 9 章（モナド） | 47 / 50 | −0.5σ |

第 8 章では偏りを疑い、**種を 20 通り変えて平均 50.1** を確認しました。生成器ではなく揺れでした。

**しきい値に 4σ 取っている理由が実データで裏づきました。** なでしこ3 版は 1.58σ で、CI が確率 5.7% で落ちていました。

### 7. 3 経路目が、その経路でしか出ない欠陥を捕まえた

なでしこ3 版と同じことが起きました。**`jsonb` の正規化は保管経由でしか出ません。**

| 経路 | 通るもの |
| :--- | :--- |
| ドメイン直接 | ハブと畳み込み |
| HTTP 経由 | 上 + パスの分解と HTML |
| **保管経由** | 上 + **JSON の往復と SQL** |

シナリオは 1 行も変えていません。第 3 章のトレイトに 3 つめの実装を足しただけです。

### 8. clippy が法則のテストを 2 度目に止めた

右恒等則（`m.and_then(Ok)` は `m` と同じ）が `bind_instead_of_map` で止まりました。第 7 章の `map_identity` と同じ形です。

**言語が構造を与えると、その構造を確かめるテストが「無駄なコード」に見えるようです。**
