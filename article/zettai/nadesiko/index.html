    Zettai — なでしこ3 版¶

    ToDo リストアプリケーション Zettai を TDD で一から作りながら、オブジェクト指向から関数型へ設計を移していく連載のなでしこ3 版です。

    想定読者は、動的型付けの言語で設計を良くしていきたい開発者です。 なでしこ3 の経験も関数型プログラミングの経験も要りません。日本語プログラミングに触れたことがなくても読めます。

    この版の焦点¶

    Kotlin 版 と同じ 13 章を、型システムを持たない言語で辿り直します。なでしこ3 には次がありません。

    • 型注釈もコンパイル時の型検査もない
    • クラス構文も、独自の型を定義する仕組みもない
    • 代数的データ型（直和型）を表す手段がない
    • モナドを書くための記法（do 記法や for 内包表記）がない

    それでも同じ設計に到達できます。Kotlin 版でコンパイラが担っていた保証を、この版ではテストが肩代わりします。 13 章を読み終えると、「型で保証する」と「約束とテストで保証する」の違いが、具体的なコードの形として分かります。

    これは教材です。 認証・認可、HTML エスケープ、CSRF 対策、スナップショットは扱いません。そのまま本番で使わないでください。

    開発環境¶

    nix develop .#nadesiko
cd apps/nadesiko/zettai
make check

    第 2 章以降はアプリケーションを起動できます。

    make run
    項目 内容
    処理系 cnako3（npm パッケージ nadesiko3 3.8.7、Node 実装。ADR-013）
    Node 22 以上
    テスト 自作の検証関数とテストランナー（ADR-014）
    HTTP plugin_httpserver（簡易 HTTP サーバ）
    永続化 追記型イベントログのファイル保存（第 9 章）

    章の目次¶

    章 タイトル この章の焦点
    1 新しいアプリケーションを準備する 題材の設定と、テストフレームワークの無い言語でテストに開発をガイドさせる前提を置く
    2 関数を使って HTTP を扱う 簡易 HTTP サーバとハンドラ関数の合成で、動く最小の縦串を通す
    3 ドメインの定義とテスト 受け入れテストを高階関数で抽象化し、ドメインとインフラを分離する
    4 ドメインとアダプタのモデリング 関数値を辞書に詰めた依存性注入で、アダプタを差し替え可能にする
    5 イベントで状態を変更する 状態変更をイベントの畳み込みとして表し、モノイドを見出す
    6 コマンドを実行してイベントを生成する コマンドからイベントを生成する関数型ステートマシンを書く
    7 関数型手法によるエラーハンドリング 例外をやめ結果辞書で失敗を運び、契約をテストで守る
    8 ファンクタを使ってイベントを射影する 射影でクエリ側を分離し、CQRS に到達する
    9 モナドによる安全なデータ永続化 追記型イベントログへの永続化を結果連鎖で安全に組み立てる
    10 コンテキストを読み込み、コマンドを処理する 文脈を受け取る関数でトランザクション相当の処理をまとめる
    11 アプリカティブによるデータバリデーション 複数のエラーを集約する検証を合成する
    12 監視と関数型 JSON 構造化ロギングと辞書 ⇄ JSON の双方向変換を扱う
    13 関数型アーキテクチャの設計 設計判断を総括し、Kotlin 版と対比する

    代数構造は第 5・7・9・11・12 章で 1 つずつ出てきます。型が無いので、構造そのものではなく「その構造が守る約束」をテストで確かめる形になります。
