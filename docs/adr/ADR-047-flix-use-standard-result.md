# ADR-047 Flix 版は標準の Result を使い、Outcome を作らない

日付: 2026-11-02

## ステータス

2026-11-02 承認されました

## コンテキスト

第 7 章で、失敗を値として運ぶ型を決めます。既存の対象の手段は次のとおりです。

| 対象 | 手段 |
| :--- | :--- |
| Kotlin | 自作の `Outcome` |
| Kotlin FP | Arrow の `Either` |
| なでしこ3 | 辞書 |
| Rust | 標準の `Result`（[ADR-031](ADR-031-own-error-enum.md) は失敗側の型だけを自作した） |

Flix には、標準の `Result[e, a]` があります。第 6 章の `handle` で、すでに `Result[ZettaiError, List[ToDoListEvent]]` を使っています。

**使う判断も、作る判断と同じく記録に値します。** 標準のものをそのまま使うとき、何を確かめたのかを残します。

### 確かめたこと

| 項目 | 結果 |
| :--- | :--- |
| `Result.map` が恒等則と合成則を満たすか | 端の値（`Int32` の最小値と最大値）と 4 種類の失敗を含む全パターンで満たす |
| 法則のテストが壊れた `map` を見分けられるか | 成功値に関数を 2 回当てる `map` で、恒等則は通り、合成則は落ちる |
| `Result` が `Functor` の型クラスのインスタンスか | `Functor.map` が `Result`・`Option`・`List` で同じ形で使える |
| `forM` で `Result` の連鎖を書けるか | 第 6 章の `handle` で、3 段の連鎖を書いた |
| 戻り値の型を `Option` から `Result` に変えたときの波及 | 直したのは 4 ファイル（`Hub`・`Lookup`・`Http`・`TestHub`）。ドメイン、イベント、遷移表、コマンドは変わらない |

## 決定

**標準の `Result` を使います。`Outcome` に当たる型を作りません。**

失敗側の型 `ZettaiError` は自作します。標準の `Result` は成功と失敗の入れ物であって、業務上ありうる失敗の集合までは与えないからです。

### 採った理由

- 必要な操作（`map`、`forM`）が標準にそろっている
- 法則を、自分で確かめた範囲で満たしている
- 型変更の波及が小さい。自作の型を挟んでも、この数字は変わらない

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `Outcome` を自作する | 標準の `Result` と同じ操作を作り直すことになる。法則のテストも書き直しになる |
| 失敗を文字列にする | テストが文字列を解析することになる。判断に使った値を失う |
| 失敗を例外にする | 型のシグネチャに現れない |

## 影響

- 自作する型は `ZettaiError` だけで、`Outcome` に関するコードが無い
- 失敗の種類を足すときは、`ZettaiError` にケースを足す。`match` が全ケースを求めるので、HTTP への写像の更新漏れはコンパイルで見つかる

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| 複数の失敗を集めること | `Result` は最初の失敗で止まる。第 11 章で、集める型が要るかを判断する |
| 標準の `Result` が将来変わること | Flix の版を `flix.toml` で固定している。上げるときは、法則のテストを再実行する |
| 標準の `Result` のすべての操作を確かめたこと | 確かめたのは `map`・`forM`・`Functor.map` だけ。ほかの操作を使うときは、その時点で確かめる |

## コンプライアンス

- `Outcome` に当たる型を作らないこと
- 失敗の種類を足したとき、`Http.statusOf` の `match` が全ケースを覆うこと（コンパイラが検査する）
- `Result.map` の法則のテストが、壊れた `map` を見分けられること
