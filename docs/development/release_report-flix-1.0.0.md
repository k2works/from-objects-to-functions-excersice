## 3 つの問いへの答え

[第 13 章](../article/zettai/flix/chapter13.md) に書いた答えの要約です。

1. **核と殻の分離は楽になったか。** 規約で守っていたことの一部を、コンパイラが肩代わりした。移せなかったのは、効果の分類の正しさ、境界の置き方、載せないものの決め方
2. **Java 相互運用の境界で、保証はどこまで届いたか。** Java のコールバックの中身と、`Logger` の処理の置き場所で切れた。Java の呼び出しの効果は一律ではなかった
3. **効果ハンドラは、DI の代わりになるか。** 文脈の持ち回りでは足りた。置き換えなければならない理由は、見つからなかった

1 つの題材、1 つの実装、Flix 0.79.0 での観察です。一般論の根拠はありません。

## 失敗と、その直し方

**CI で一度落ちました。** Unit 5 で、`EventStore` の戻り値を `Result` に変えたところ、第 3・6・8 章の記事のコード例が実装とずれて、記事の検査（`check_article_code.py`）が CI で失敗しました。push の前に記事の検査をローカルで回さなかったためです。該当のコードブロックに、書いた時点のコミットを示す `code-check: ignore` を付けて直しました。以後は、実装を変えるたびに、先に検査を回しました。

**コミットの混入が一度ありました。** Unit 6 で、実装のコミットに記事のファイルが混ざりました。push の前だったので、コミットを作り直して、実装と記事を分けました。

- **push の前に検査を回す。** 記事のコードと実装のずれは、CI の前にローカルで見つけられる
