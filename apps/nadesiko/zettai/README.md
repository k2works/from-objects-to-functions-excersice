# Zettai（なでしこ3 版）

連載 [Zettai — 関数型プログラミングで作る変更を楽に安全にできるソフトウェア](../../../docs/article/zettai/nadesiko/index.md) のなでしこ3 版サンプル実装です。

## 実行環境

```text
nix develop .#nadesiko
cd apps/nadesiko/zettai
make check
```

`nix develop` の初回だけ `npm install` が走り、`node_modules/` に cnako3 が入ります。

| 項目 | 内容 |
| :--- | :--- |
| 処理系 | cnako3（npm パッケージ `nadesiko3` 3.8.7、Node 実装） |
| Node | 22 以上（`nadesiko3` の `engines` が要求する） |
| バージョンの固定先 | `package.json` の 1 箇所のみ |

## タスク

| コマンド | 内容 |
| :--- | :--- |
| `make check` | **最新の段階だけ**を検査する（書いている間はこれ） |
| `make check-all` | 全段階を検査する（CI が毎回回す） |
| `make lint` | 全 `.nako3` を構文解析だけして文法エラーを見つける |
| `make test` | `test/stepN/*_test.nako3` を 1 本ずつ実行する |
| `make doctest` | `doctest/stepN/` の受け入れシナリオを段階ごとに実行する |
| `make run` | 最新の段階のアプリケーションを実行する |
| `make clean` | 生成物を削除する |

## ディレクトリ

**章の段階ごとにディレクトリを分けています**（[ADR-015](../../../docs/adr/ADR-015-step-directories.md)）。過去の章のコードがその場に残るので、記事のコード例が実装から消えません。

```text
apps/nadesiko/zettai/
├── package.json         cnako3 のバージョンを固定する
├── Makefile             タスクランナー兼テストランナー
├── src/step1/*.nako3    第 1〜3 章（Unit 1〜2）
├── src/step2/*.nako3    第 4〜7 章（Unit 3〜4）
├── test/stepN/
│   ├── helper.nako3     検証関数とテスト結果報告
│   ├── ddt/             受け入れテストの入口と実行経路
│   └── *_test.nako3     テスト
└── doctest/stepN/       受け入れシナリオ（HTTP 経由）
```

段階の区切りは Kotlin 版のモジュール（`zettai-stepN-*`）と揃えています。**過去の段階は凍結します。**

**`make check` は最新の段階だけを対象にします。** ファイルごとに cnako3 のプロセスを起こすため、段階が増えると全段階の実行は長くなります。書いている間の待ち時間を短く保つため、既定を最新段階にしています（約 12 秒）。

全段階は `make check-all` です（8 コアで 3 段階・約 24 秒）。**CI が push のたびに回します。** 特定の段階だけを見たいときは `make check STEP=step1`、並列数は `make check JOBS=4` で変えられます。

## この実装の約束

なでしこ3 には型システムがありません。Kotlin 版でコンパイラが担っていた保証を、この実装ではテストが肩代わりします。

1. **値を比べる前に型を比べる。** `test/helper.nako3` の `検証` は、`変数型確認` 同士を先に比べます。なでしこ3 の `=` は型を区別せず、`3` と `「3」` が等しくなるためです
2. **辞書を返す関数には契約テストを 1 本置く。** キーの有無と値の型を確かめます（第 4 章以降）
3. **識別子にひらがなを使わない。** ひらがなは助詞として切られ、文法エラーになります
4. **過去の段階は凍結する。** `src/step1/` は第 1〜3 章の記事が説明しているコードです

## 注意

なでしこ3 は**実行時エラーでも終了コードが 0** になります。テストの合否は `テスト結果報告` が失敗時に `1でプロセス終` を呼ぶことで、文法エラーは `cnako3 -A` の標準エラー出力が空でないことで判定しています。どちらも `Makefile` に実装しています。

## 既知の制約

なでしこ3（cnako3）で踏んだ制約をここに集めています。**設計を始める前にここを読んでください。** 同じつまずきを 3 度繰り返したので作りました（Unit 5 のふりかえり Try 1）。

### 言語・処理系

| # | 制約 | 対処 | 初出 |
| :--- | :--- | :--- | :--- |
| 1 | **関数値ごしに呼ぶと、中の非同期な組み込み命令が待たれず Promise が返る** | 入出力を関数値の外に出す。副作用を端に寄せる | 第 3 章・第 7 章・第 9 章（**3 回踏んだ**） |
| 2 | 実行時エラーでも**終了コードが 0** | `プロセス終` で明示し、出力の「…エラー]」も見る | 第 1 章 |
| 3 | `=` も `ASSERT等` も**型を区別しない** | 値の前に `変数型確認` 同士を比べる | 第 1 章 |
| 4 | `変数型確認` は**配列と辞書を区別しない**（どちらも `object`） | 要素数や鍵の有無で確かめる | 第 2 章 |
| 5 | 辞書に無いキーは `undefined` で、**`空` では捕まえられない** | `辞書キー存在` で先に確かめる | 第 2 章 |
| 6 | **`繰り返す` は開始が終了より大きくても逆向きに回る** | 空の入力にガードを置く | 第 3 章 |
| 7 | **配列を削りながら自分を呼ぶ再帰が書けない**（自己参照が解決されない） | ループで書き、外から見た振る舞いを保つ | 第 5 章 |
| 8 | `配列逆順` などが**破壊的** | `配列複製` してから使う | 第 5 章・第 8 章 |
| 9 | 辞書に**複製の命令が無い** | キーを写す関数を自作する | 第 5 章 |
| 10 | ファイルに**追記の命令が無い** | 読んで足して書き戻す | 第 9 章 |
| 11 | **既定引数が無い** | 入口を複数用意する | 第 4 章 |
| 12 | **列挙型が無い** | 取りうる値を一覧に集め、契約テストで網羅を守る | 第 4 章・第 7 章 |
| 13 | **直和型が無い** | `種別` キーの文字列で区別し、契約テストで守る | 第 6 章 |
| 14 | 文字列の中で `\"` は**エスケープされない** | HTML の属性はシングルクォートで書く | 第 11 章 |

### 名前の付け方

| # | 制約 | 対処 |
| :--- | :--- | :--- |
| 15 | **識別子のひらがなは助詞として切られる** | 漢字・カタカナ・英数字で組む |
| 16 | **組み込み命令名は変数名に使えない**（`合計`・`追加`・`参照`・`倍`・`読`・`次`・`戻し` など） | 別の名前にする。エラーが教えてくれる |
| 17 | 助詞は**引数の一部**。`への` は助詞ではない | 定義と呼び出しで助詞を揃える |

### 書き方

| # | 制約 | 対処 |
| :--- | :--- | :--- |
| 18 | **式の中に関数呼び出しを入れ子にすると落ちる**ことがある | 一度変数に受ける |
| 19 | 関数値を引数に渡すときは**カッコで包む**。`{関数}` を式の中に書くと呼び出しになる | 定義済みの名前はカッコ、`{関数}` からは変数に受ける |
| 20 | プラグインの取り込みは**相対パス**が要る | `!「../../node_modules/nadesiko3/src/plugin_httpserver.mjs」を取り込む` |
