# ADR-029 段階を切る手順を決める

日付: 2026-09-29

## ステータス

2026-09-29 提案されました

## コンテキスト

[ADR-015](ADR-015-step-directories.md) が「章の段階ごとにディレクトリを切り、過去の章のコードを残す」と決めています。**何のために切るかは書いてありますが、どう切るかは書いてありません。**

3 対象を通して、**この持ち込みを 3 回送りました**（Rust 版 Unit 1 → 2 → 3）。第 4 章で 2 つめの段階を切るので、ここで決めます。

### 実測した

`zettai-step2-domain` / `zettai-step2-http` を仮に作り、3 つの構成で測りました。**依存クレートのキャッシュを揃えてあります。**

| 構成 | 初回（新しい段階だけ clean） | 定常 |
| :--- | :--- | :--- |
| (a) 両段階が `bin` を持つ（同名） | 18.21 / 12.28 秒 | 5.32 / 5.11 秒 |
| (b) `bin` は最新段階だけが持つ | 14.90 / 12.33 秒 | 4.97 / 5.25 秒 |
| **(c) 両段階が持ち、名前を分ける** | **14.03 / 13.57 秒** | **6.38 / 5.36 秒** |

**差は誤差の範囲でした。** 段階を 2 つにしたときの `just check` は定常 4.07 秒 → 5〜6 秒で、上限 20 秒に対して余裕があります。

はじめは「初回 24.77 秒で上限を超える」と見ていましたが、**それは段階を増やした代償ではなく、依存クレートを初めてビルドした値**でした。測り直して分かりました。

### 同名の `bin` は衝突する

段階をそのまま複製すると、実行ファイルの出力名が重なります。

```text
The bin target `zettai` in package `zettai-step2-http` has the same output filename
as the bin target `zettai` in package `zettai-step1-http`.
This may become a hard error in the future; see https://github.com/rust-lang/cargo/issues/6313
```

**いまは警告ですが、将来はエラーになります。**

## 決定

**段階を切る手順を次のとおりにします。**

1. **切るのは、章がコードの形を変えるときだけ。** 章が増えるたびには切らない。Rust 版は第 4 章（関数型 DI）で 2 つめを切る
2. 直前の段階を**そのまま複製**し、クレート名の `stepN` だけを上げる
3. **`[[bin]] name` を段階ごとに分ける。ファイル名は変えない**

    ```toml
    [[bin]]
    name = "zettai-step2"
    path = "src/bin/zettai.rs"
    ```

4. `workspace.members` に 2 つ（domain と http）を足す
5. `just check` を測り、**上限を超えていないことを確かめてから**先に進む
6. **`check_article_code.py` を回し、落ちた過去章を [ADR-015](ADR-015-step-directories.md) の規則で処理する**
    - その章の**主題でない**引用（構成ファイルなど）→ **最終形に直す**
    - その章の**主題そのもの**の引用 → `<!-- code-check: ignore 理由 -->` を付け、どの章で置き換わるかを書く
7. 過去の段階には**一切手を入れない**

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `bin` は最新段階だけが持つ | 利点は #6313 の警告が消えることだけで、それは名前を分けても得られる。**第 2 章が `src/bin/zettai.rs` を指しているので、記述が 2 箇所で嘘になる** |
| `bin` のファイル名を段階ごとに変える | 同上。`[[bin]] name` だけで足りる |
| 段階を切らず、最新形だけを置く | 記事が指すコードが章をまたいで変わり続ける。[ADR-015](ADR-015-step-directories.md) の否定 |
| 章ごとに切る | 段階が 13 個になる。ビルド時間が線形に増え、複製も増える |

### 追記: ゲートに載せるのは、基準で決まらないときだけ（2026-09-29）

上の「Unit の計画時に決め、ゲートに載せます」は、[リリース計画](../development/release_plan-rust.md) のゲート規約 1（**選択肢と数字を添えられないものは、ゲートにしない**）とぶつかります。

Unit 4 で実際にぶつかりました。第 7 章は失敗する関数すべての戻り値の型を変えるので、**上の基準で答えが決まってしまい、選択肢が立ちません**。

**規約 1 を優先します。** 段階を切るかは、次のとおりに扱います。

| 状況 | 扱い |
| :--- | :--- |
| 基準（章がコードの形を変えるとき）で答えが決まる | **DoD の項目にする。** 切ったあとに秒数を測って記録する |
| 基準で決まらない（形が変わるとは言い切れない） | **ゲートに載せる。** 選択肢と秒数を添える |

## 影響

- 段階を切るたびに **`Cargo.toml` が 2 個、クレートが 2 つ増えます**
- `just check` は段階の数に比例して伸びます。**Unit ごとに測り、上限 20 秒を割らないことを確かめます**
- 過去章の記事が落ちるのは**構造上避けられません**。手順 6 で処理します
- 同じコードが段階の数だけ複製されます（[ADR-015](ADR-015-step-directories.md) と同じ代償）

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **どこで切るかの判断そのもの** | 「章がコードの形を変えるとき」は基準であって計算式ではありません。**Unit の計画時に決め、ゲートに載せます** |
| 段階が増えたときの上限 | 段階 5 つで上限を超えたらどうするかは決めていません。**超えたときに判断します**（[ADR-026](ADR-026-just-and-coverage.md) と同じ扱い） |
| 過去段階のコードの寿命 | いつまで残すか。連載が終わるまで残す前提ですが、**保守の対象にはしません**（`just check` が通ることだけを守ります） |
| 他の 2 対象への適用 | Kotlin 版・なでしこ3 版は完結しているので、さかのぼって適用しません |

## コンプライアンス

- 段階ごとの `[[bin]] name` が重複しないこと（`cargo` が #6313 の警告を出さないこと）
- 過去の段階のファイルが、切った後のコミットで変更されていないこと
- 段階を切ったコミットで `check_article_code.py` が 0 件であること
