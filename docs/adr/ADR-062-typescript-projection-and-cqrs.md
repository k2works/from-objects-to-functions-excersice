# ADR-062 TypeScript FP 版は読み取りを出来事からの射影にし、射影は保存しない

日付: 2026-11-28

## ステータス

2026-11-28 推奨案を採用しました。利用者の事前の指示「執筆完了まで、判断はすべて推奨を採用する」によるもので、人が個別に確認してはいません

## コンテキスト

第 8 章で、利用者のリストの一覧（名前、項目数、完了数）を表示します。コマンドを決めるための状態 `ToDoListState` は、利用者ごとの全項目を持ち、画面が欲しい形ではありません。

## 決定

1. **一覧は、出来事を行の形に畳み込む純粋な関数 `projectRows` で作る。** 状態を経由しない
2. **射影の結果は保存しない。** 問い合わせのたびに、利用者の出来事を読んで作る
3. **ハブの依存を、出来事の読み取り 2 つと追記にする。** `readListEvents`（コマンドと 1 つのリスト）、`readUserEvents`（一覧）、`persist`。第 6〜7 章の `fetchList`・`fetchState` は無くす
4. **ファンクタは自作しない。** 配列と `Effect` の `map` を使い、法則は性質テストで確かめる

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| 状態を作ってから、行を数える | 一覧の形を、状態の持ち方が決めてしまう。射影と書き込みの分離を、章で示せない。この計算は、射影を確かめるテストの別の道筋として使う |
| 射影を保存して、追記のたびに更新する | 古い射影が見える場合と、作り直しの手順が要る。いまの規模では、保存する理由を測っていない |
| `ToDoListProjection` を型にして、`map` を自作する | 配列と `Effect` に `map` があり、行の変換はそれで書ける |

## 影響

### ポジティブ

- 一覧の画面の形を変えても、コマンドの処理は変わらない
- コマンドは、対象のリストの出来事だけを読む。永続化で、読む行を絞れる
- 射影が保存されないので、古い一覧は見えない

### ネガティブ

- 一覧の問い合わせは、利用者の出来事をすべて読む。性能は測っていない
- 同じ出来事の解釈が、状態の `apply` と射影の 2 か所にある。出来事を足すと、両方を直す。直し忘れは、戻り値の型を持つ `switch` なので型検査が止める。解釈の食い違いは、性質テストで守る。保証するのは、生成した入力の範囲である
- 状態の変更の適用（`withStatus`）は、2 か所で共有している。この関数の誤りは、2 つの比較では見つからない

## コンプライアンス

- 射影の行が、状態から数えた行と一致することを確かめる性質テストがある。生成する列に、完了した項目が含まれる割合もテストする
- コマンドが、対象のリストの出来事だけを読むことを確かめるテストがある
