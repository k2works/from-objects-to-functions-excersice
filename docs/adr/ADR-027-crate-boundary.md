# ADR-027 境界をクレートで分け、境界検査を書かない

日付: 2026-09-29

## ステータス

2026-09-29 提案されました

## コンテキスト

第 3 章でドメインとインフラを分けます。**分けること自体は 3 対象で共通**で、違うのは分け方です。

| 対象 | 分ける手段 | 守る手段 |
| :--- | :--- | :--- |
| Kotlin | パッケージ | `DomainBoundaryTest` が import を機械的に検査（[ADR-007](ADR-007-module-per-unit.md)） |
| なでしこ3 | ファイル | `boundary_test.nako3` がファイルの中身の文字列を数える |
| **Rust** | **クレートかモジュール** | **どちらを選ぶかで変わる** |

2 対象はどちらも「**不在**を検査する」形でした。取り込んでいないことを、テストで確かめています。

Rust には選択肢が 2 つあります。

- **案A モジュール分割**: 1 クレートの中で `mod domain` / `mod http`
- **案B クレート分割**: 段階ごとに `zettai-stepN-domain` / `zettai-stepN-http`

### 実測した

両方を作り、**ドメインから HTTP を呼ぶコードをわざと書いて**確かめました。

| | 案A モジュール | 案B クレート |
| :--- | :--- | :--- |
| ドメインから HTTP を呼ぶと | **通る**（エラー 0 件） | **コンパイルが止まる**（E0433） |
| `cargo test --all` | 3 秒 | **3 秒**（変わらず） |
| `Cargo.toml` | 1 個 | 2 個 |
| 境界検査 | **書く必要がある** | **書かなくてよい** |

```text
error[E0433]: failed to resolve: use of unresolved module or unlinked crate `zettai_step1_http`
```

**ビルド時間は変わりませんでした。** 増えるのは `Cargo.toml` の数だけです。

## 決定

**段階ごとに 2 クレートに分けます。境界検査は書きません。**

1. `zettai-stepN-domain` と `zettai-stepN-http` を workspace のメンバーにする
2. 依存は **HTTP → ドメインの一方向だけ**。ドメイン側の `Cargo.toml` に HTTP を書かない
3. **ドメインのクレートは依存を 1 つも持たない**。何かを足すときは、それがドメインの言葉かを疑う
4. 境界検査を書かない。**コンパイラが守る**

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| モジュール分割（案A） | 同一クレート内は相互参照できる。**2 対象と同じく検査を書くことになり、型のある言語の利点を捨てる** |
| ドメインを段階をまたいで 1 クレートにする | 段階の意味（過去の章のコードを残す。[ADR-015](ADR-015-step-directories.md)）が壊れる |
| 境界検査も併せて書く | コンパイラが守っているものを二重に検査することになる。**守っているものが無い検査は入れない**（[ADR-026](ADR-026-just-and-coverage.md)） |

## 影響

- **境界検査を 1 行も書きません。** Kotlin 版は import の検査、なでしこ3 版は 7 ファイル × 5 項目の検査を書きました
- **依存の向きが `Cargo.toml` に現れます。** ファイルを読めば誰が誰を知っているかが分かります
- ドメインのクレートが依存 0 なので、**そこに何かを足すときに目立ちます**
- `Cargo.toml` が段階 × 2 個になります。段階 5 つなら 10 個

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **クレートの中の構造** | 1 つのクレートが大きくなったときの分け方は決めていません。第 5 章以降でドメインが育ったら見直します |
| **レイヤーが 3 つ以上になったとき** | いまは domain / http の 2 つです。第 9 章で永続化が入ると 3 つめが要るかもしれません。**そのとき判断します** |
| **循環依存の検出** | コンパイラが止めますが、**「止まった理由が設計の誤りか、単に書く場所を間違えただけか」は教えません** |
| **段階をまたぐ重複** | 段階ごとにドメインのクレートを複製するので、同じコードが増えます（[ADR-015](ADR-015-step-directories.md) と同じ代償） |

## コンプライアンス

- ドメインの `Cargo.toml` に HTTP のクレートが現れないこと
- ドメインのクレートが外部クレートに依存しないこと
- **境界検査を書かないこと**（書いたら、この決定が守られていない証拠）
