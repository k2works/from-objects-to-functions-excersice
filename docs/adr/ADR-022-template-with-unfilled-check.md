# ADR-022 テンプレートを自前で書き、埋めそこねを実行時に止める

日付: 2026-09-28

## ステータス

2026-09-28 提案されました

## コンテキスト

第 2 章から、画面は文字列の連結で作ってきました。第 11 章で画面が 2 つに増え、入力を受け取るフォームが入ります。連結のままだと、どこに何が入るかが読めなくなります。

Kotlin 版は [ADR-010](ADR-010-own-template.md) で、テンプレート機構を自前で書き、既製のテンプレートエンジンを入れませんでした。なでしこ3 版でも同じ判断ができますが、事情が 1 つ違います。

**型がありません。** Kotlin 版はデータクラスのフィールドが揃っているかをコンパイラが見ます。なでしこ3 版では、値を渡し忘れても何も言われず、画面に `{{リスト名}}` がそのまま出ます。

もう 1 つ、この処理系に固有の事情があります。**`「」` は中の `{...}` を式として展開します。** `{{タグ}}` を含む文字列を `「」` では書けません（`README.md` の既知の制約 23）。

## 決定

**テンプレートを自前で書き、未適用のタグが 1 つでも残ったら失敗にします。**

1. 雛形は展開しない `『』` で書く。埋め込みは `{{名前}}` の形にする
2. `テンプレート適用` は辞書のキーを順に置換し、**置換後に `{{` が残っていれば `TemplateNotFilled` で失敗**を返す
3. 値は骨組みに入る前に無害化する（`&`・`<`・`>`・`"`）。タグを持てるのは骨組みだけ
4. 失敗した画面は 500 で返す。`{{...}}` を利用者に見せない

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| 既製のテンプレートエンジンを入れる | 連載の主題は「言語が与えないものを自分で組む」こと。第 1 章から一貫して自前で書いている |
| 埋めそこねを黙って空文字列にする | 渡し忘れが画面から消え、気づけなくなる。型が無いぶん、実行時に止めるしかない |
| 埋めそこねを警告だけにする | 警告は読まれない。Unit 5 の学び「懸念を書くだけでは防げない。検査が止める」に反する |
| 連結のまま書き続ける | 画面が増えると骨組みと値が混ざる。第 11 章でフォームが入り、限界が来た |

## 影響

- **渡し忘れが必ず止まります。** 型検査の代わりを実行時の検査が務めます
- 値の無害化が 1 か所に集まります。画面ごとに書き分ける必要がありません
- 骨組みそのもの（項目の並びなど）を差し込むときは、テンプレート適用の前に自前で置換します。**無害化されない箇所がここだけ残ります**

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **雛形の静的検査** | どのキーが要るかを事前に知る手段はありません。実行して初めて分かります |
| **骨組みの差し込み** | 項目の並びは無害化を通しません。差し込む値がドメイン由来であることに依存しています |
| **雛形の再利用** | 雛形は関数として置くだけで、部分テンプレートの仕組みはありません。画面が増えたら見直します |

## コンプライアンス

- 雛形が `『』` で書かれていること（`「」` では `{{` を書けない）
- 埋めそこねたテンプレートが 200 で返らないこと（`test/stepN/template_test.nako3`・`web_test.nako3`）
