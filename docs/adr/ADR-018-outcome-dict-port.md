# ADR-018 失敗を結果辞書で表し、ポートの契約を変える

日付: 2026-09-28

## ステータス

2026-09-28 提案されました

## コンテキスト

第 2 章から「見つからない」を `空` で表してきました。第 6 章では拒否を「イベント 0 件」で表しました。どちらも暫定です。

**`空` は情報を持ちません。** なでしこ3 の `空` は空文字列で、「値が無い」「空文字列そのもの」「まだ調べていない」を区別しません。加えて、辞書に無いキーを引くと `undefined` が返り、これは `空` とも違います（第 2 章のつまずき 3）。

「イベント 0 件」も同じです。同名のリストがあったのか、リストが無かったのか、遷移が許されなかったのかが分かりません。

Kotlin 版は `Outcome<E, T>` を導入し、**ポートの型を変えました**（[ADR-006](ADR-006-outcome-port-type.md)）。型が変われば、その型を触る場所がコンパイルエラーになります。

**なでしこ3 では何も起きません。** 契約を変えても、呼び出し側は `undefined` を読んで動き続けます。

## 決定

**失敗を、理由を持つ結果辞書で表します。ポートの契約を変えます。**

1. 結果は `{"成功":真,"値":…}` または `{"成功":偽,"理由":…}`
2. 失敗の理由は 4 種類（`ListNotFound`・`ItemNotFound`・`ListAlreadyExists`・`InvalidTransition`）。列挙型が無いので `失敗理由一覧` に集め、契約テストが網羅を守る
3. `結果マップ` を定義する。成功なら中の値に適用し、失敗は素通しする。**これがファンクタ**で、恒等則と合成則を性質テストで確かめる（[ADR-017](ADR-017-own-property-testing.md)）
4. **契約テストを実装より先に変える。** 落ちたテストの一覧が、型検査の代わりに波及を教える
5. 失敗の理由と HTTP のステータスコードの対応表は `outcome.nako3` に置き、**ドメインは HTTP を知らない**まま HTTP の層がそれだけを見る

### 波及の実測

契約を変えたときに壊れた箇所は **5 つ**でした。

| 段階 | 壊れた箇所 |
| :--- | :--- |
| 契約テストを先に変えた時点（3 件） | `events_test`・`commands_test`・`hub_test` |
| 実装を変えた後に判明（2 件） | `web.nako3`・`ddt/actions_domain.nako3` |

**先にテストを変えて見つかったのは 3 件で、残り 2 件は実装を変えて実行するまで分かりませんでした。** 型があれば 5 件すべてが一度に分かります。契約テストは型検査の代わりになりますが、**テストが無い場所は教えてくれません**。

## 影響

- **失敗の理由が呼び出し側に届きます。** ブラウザは 404 と 400 を区別でき、理由も表示できます
- **`結果マップ` がファンクタです。** 第 8 章の射影、第 9 章のモナド、第 11 章のアプリカティブが同じ形の上に乗ります
- **契約テストの網羅が、そのまま波及検出の網羅です。** テストの無い場所は静かに壊れます。これは型のある言語には無いリスクで、第 7 章に書きます
- ドメインは HTTP を知りません。対応表だけが両者をつなぎます

## コンプライアンス

- ポートが `空` ではなく結果を返すこと
- 失敗の理由が 4 種類すべて契約テストで確かめられていること
- ステータスコードの対応が 4 種類すべて確かめられていること
- `結果マップ` の恒等則と合成則が性質テストで green で、**壊すと落ちること**
- 契約を変えるときは、**実装より先にテストを変える**こと

## 再検討の条件

1. 失敗の理由が 8 種類を超え、文字列の約束では扱いきれなくなる
2. 第 9 章で `結果` にモナドの `flatMap` 相当を足すとき、辞書の形が足りなくなる
3. 契約テストの無い場所で、契約の変更に起因する欠陥が実際に起きる
