# Zettai — Kotlin 版

Kotlin で Zettai を実装しながら、関数型の設計手法を積み上げていきます。原著『From Objects to Functions』と同じ題材・章構成ですが、コードはすべて本リポジトリで書き起こした自作実装です。

**想定読者**: オブジェクト指向で設計・実装してきた開発者です。関数型プログラミングの経験は要りません。Kotlin を読めれば足ります（使う機能は各章で説明します）。

**13 章を読み終えて得られるもの**: 5 つの代数構造（モノイド・ファンクタ・モナド・アプリカティブ・プロファンクタ）を**いつ選ぶかの判断軸**と、設計の規則をテストで検査するという習慣です。用語の解説ではなく、1 つのアプリケーションを 13 章かけて作り替える過程として書いています。

> **これは教材です。そのまま実務に出せません。** 認証・認可を実装していないため、URL を知っていれば誰でも他人のリストを操作できます。ほかに HTML エスケープ・CSRF 対策・JSON エスケープ・スナップショットを扱っていません（[第 13 章の「扱わなかったこと」](chapter13.md)）。

## 開発環境

```bash
nix develop .#kotlin
cd apps/kotlin/zettai
./gradlew check
```

動かして構造化ログ（第 12 章）を見る場合は次を実行し、`http://localhost:8080/todo/uberto/book` を開きます。

```bash
./gradlew :zettai-step5-monitoring:run
```

| 項目 | 内容 |
| :--- | :--- |
| 言語 | Kotlin 2.x |
| JDK | 21 |
| ビルド | Gradle（マルチプロジェクト、`gradle/libs.versions.toml` でバージョン管理） |
| Web | http4k |
| テスト | JUnit 5、Strikt、Pesticide（DDT） |
| 永続化 | PostgreSQL（JDBC 直。第 9 章以降。[ADR-008](../../../adr/ADR-008-event-store-single-table.md) で ORM を使わない判断） |
| JSON | 自前の `Converter`（第 12 章。[ADR-012](../../../adr/ADR-012-own-json-converter.md) で Kondor を採用せず） |

第 9 章以降の結合テストで使う PostgreSQL は、リポジトリ既存の `docker-compose.yml` のサービスを利用します。

## 章の目次

**全 13 章が公開済みです（13 / 13）。** 途中の章から入る場合は「この章の焦点」を目安にしてください。

| 章 | タイトル | この章の焦点 |
| :--- | :--- | :--- |

| 2 | [関数を使って HTTP を扱う](chapter02.md) | 関数合成で HTTP を扱い、動く最小の縦串を通す |
| 3 | [ドメインの定義とテスト](chapter03.md) | 受け入れテストを高階関数で抽象化し、ドメインとインフラを分離する |
| 4 | [ドメインとアダプタのモデリング](chapter04.md) | 関数型の依存性注入で、アダプタを差し替え可能にする |
| 5 | [イベントで状態を変更する](chapter05.md) | 状態変更をイベントの畳み込みとして表し、**モノイド**を見出す |
| 6 | [コマンドを実行してイベントを生成する](chapter06.md) | コマンドからイベントを生成する関数型ステートマシン |
| 7 | [関数型手法によるエラーハンドリング](chapter07.md) | 例外ではなく `Outcome` で失敗を型に載せ、**ファンクタ**を理解する |
