## 判断と学び

### 1. ゲートが 3 / 3 で同期停止した

**累計 14 / 14（100%）**です。なでしこ3 版の 41 箇所中 1 回に対し、ここまで **14 箇所中 14 回**です。

| ゲート | 決め手 |
| :--- | :--- |
| 文脈とトランザクションの境界 | **ドメインのライフタイム注釈（0 対 8）と `commit` を誰が呼ぶか** |
| 複数のエラーを集める型 | **結果は 3 案とも同じ。「合わせる操作が出るか」が分けた** |
| テンプレートの既製品 | **Kotlin 版の自作理由が成り立たないこと** |

**3 つとも「結果が同じでも形が違う」判断でした。** 数字だけでは決まらず、**何を見せたいか**が決め手になっています。

### 2. Kotlin 版の設計が型システムに拒まれた

第 10 章です。**2 つの形が書けませんでした。**

| 落ちた形 | エラー |
| :--- | :--- |
| 単位を値として返す | **E0515 + E0505**（自己参照） |
| **[ADR-011](../adr/ADR-011-transaction-boundary.md) の決定 2**（空の文脈 + ダウンキャスト） | **E0478**（`dyn Any` が `'static` を要求） |

**「できなかった」で終わりませんでした。** 文脈にドメインの動詞を持たせた結果、**Kotlin 版が `require(context is JdbcContext)` で妥協していた実行時検査が要らなくなりました**。

なでしこ3 版は「言語に何かが足りないから」移植できませんでした。**Rust では「言語が持っている規則に拒まれた」**という逆の形です。

### 3. Kotlin 版と違い、ポートの型から失敗が消えなかった

Kotlin 版は `HubAction` を入れた結果、ポートの戻り値から `Outcome` が消えました。**トランザクションと引き換えに、型に現れる失敗を失っています。**

**Rust 版はどちらも失っていません。** 区間として貸す形にしたので、遅延させる必要がありませんでした。

代償は「単位の戻り値が `ToDoList` に固定される」ことです（`<T>` を入れるとオブジェクト安全でなくなります）。

### 4. 3 対象で初めて既製品に寄せた

第 11 章のテンプレートです。

| 章 | 既製品 | 判断 |
| :--- | :--- | :--- |
| 3 | `cucumber` | 入れず（依存 +121・ビルド +92 秒） |
| 5 | `proptest` | 入れず（依存 +38・26.77 秒） |
| 7 | `thiserror` | 入れず（依存 +10・12.29 秒） |
| 9 | `serde_json` | 入れず（依存 +5・8.30 秒） |
| **11** | **`tera`** | **入れた**（依存 +3・18.42 秒） |

**数字だけで決まったのではありません。** Kotlin 版が自作した理由は「既製品は未適用のタグを失敗にできない」で、**`tera` は既定で `Result` を返します**。理由が消えたので、自作すると理由のない自作になります。

### 5. 既製品を入れても、既定が安全とは限らなかった

入れてすぐテストが落ちました。

```text
生のタグが残っている: <li><script>alert(1)</script></li>
```

**`tera` の自動エスケープはテンプレート名の拡張子で決まります。** `"list.html"` にして通りました。

### 6. 計画の具体例が、経路によって作れなかった

**なでしこ3 版と同じ形の手戻りです。**

計画には「利用者名が空 かつ 新しいリスト名が 41 文字」と**実物で**書いていました。それでも足りませんでした。**利用者名はパスから来るので、HTTP 経路では空にできません**（`/todo//book/rename` は空の部分が落ちて 3 要素になります）。

**「実物を書く」の次に「すべての経路で作れるか」が要る**と分かりました。1 つの値に 3 つの規則をかける形に置き直しています。

### 7. 自分の出力だけで往復させる欠陥の 2 件目

`tiny_http` が渡すボディを実物で確かめたら、**パーセントエンコードされて届いていました**。

```text
Some("%E8%AA%AD%E3%82%80 %E6%9C%AC%26%22%3Cx%3E%22")
```

**第 4 章から使っている `description_in` は `+` しか戻していません。** ASCII だけの説明を使っていたので、受け入れテストは通り続けていました。

第 9 章の `jsonb` に続いて 2 件目です。**Unit 5 の Try 2（往復テストは相手が返した形でも書く）が効きました。**

### 8. 依存を足したら検査が遅くなった（持ち込み 6 の確認）

| | 前 | 後 |
| :--- | :--- | :--- |
| `just check`（外・定常） | 9.37〜12.89 秒 | **15.86〜16.39 秒** |
| `just check`（内・定常） | 7.82〜8.76 秒 | **12.36〜13.20 秒** |

**Unit 5 の学び（フィーチャで隠せるのはテストの実行だけ）がそのまま出ました。** 上限 20 秒までの余裕が 4 秒を切っています。

### 9. カバレッジの数え方を直した

`just cov` が落ちました。**89.67%** です。

原因は `db` フィーチャの裏のコード（`event_store.rs` が 30.80%）で、**段階を切るたびに未到達が積み上がります**。第 9 章の `src/bin/` と同じ形です。

`check-all` はすでに docker を要求しているので、**`cov` を DB のジョブへ移して `--all-features` で数える**ようにしました。**94.68%** になっています。
