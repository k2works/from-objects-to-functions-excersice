# ADR-066 TypeScript FP 版はログを decorator で足して項目名で絞り、変換は両方向の型にする

日付: 2026-11-28

## ステータス

2026-11-28 承認されました（実装と章の公開の後に、人がまとめて承認しました）

それまでの経緯: 2026-11-28 推奨案を採用しました（Unit 7 のゲート）。**同期停止していません。** 利用者の事前の指示「執筆完了まで、判断はすべて推奨を採用する」によるもので、人が個別に確認してはいません。**利用者名とリスト名をログに載せる判断も、個別の確認を受けていません**

## コンテキスト

第 12 章で、動きを後から追えるようにします。第 7 章から、500 の原因を残していませんでした。ログに何を載せ、何を載せないかと、JSON との変換の表し方を決めます。

## 決定

1. **ログは decorator で足す。** 保管の 3 つの操作（`loggedPorts`）と、HTTP の要求（`loggedApp`）を包む。ハブ、domain、web の本体は、ログを知らない
2. **Effect の `log`・`annotateLogs` は使わず、自作の記録の型と出力にする。** 出力先と時刻は引数で渡す
3. **書き出すときに、許可した項目名だけを通す。** 型だけでは余分な項目を止められないことを確かめたため
4. **載せるのは、操作の種類、結果（成功、業務の失敗の種類、例外のクラス名、中断）、利用者名、リスト名、件数、所要時間、要求のメソッド・パス・状態。** 項目の説明、例外のメッセージとスタックトレース、クエリ、本文は載せない
5. **出力先の失敗は握りつぶし、本体の結果を変えない**
6. **JSON との変換は、書きと読みをまとめた `JsonCodec<In, Out>` にし、`dimap` を持つ。** 書いて読むと戻ることは、法則とは別の性質テストで確かめる
7. 保存の読み書きの実装は、第 9 章の形を変えない。`eventCodec` は、その 2 つの関数をまとめたもの

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `Effect.annotateLogs` と Effect の logger | 載せる項目が任意の値で、型でも出力でも絞れない形になる。**出力の形や機能は比べていない** |
| 型で項目を限定するだけにする | 型に無い項目を、直接書いても、展開で足しても、型検査が通った |
| `Schema` で書きと読みを 1 つの定義にする | 保存の形を作り直すことになる。往復は性質テストで確かめた。**作り比べていない** |
| 例外のメッセージも載せる | 接続先などの機密が混ざりうる |
| 利用者名とリスト名を載せない | 障害の対象を追えなくなる（Kotlin 版は、人の承認を得て載せた） |

## 影響

### ポジティブ

- 型に無い項目や、構造的に紛れ込んだ項目は、出力に出ない
- 500 の原因の種類が、ログに残る

### ネガティブ

- 例外のメッセージが残らないので、原因を特定できない場合がある
- 利用者名とリスト名、要求のパスは、個人を特定しうる。ログの保管とアクセスの管理は、この版では扱っていない
- 項目の絞り込みは名前だけで行う。許可した名前の項目に機密を入れると、出る
- 出力先が失敗すると、その行は失われ、失われたことも分からない
- 接続の読み取りの失敗や 413 など、アプリケーションに届く前の失敗は、ログに残らない
- `dimap` は、本体のコードでは使っていない

## コンプライアンス

- 項目の説明、クエリ、本文、例外のメッセージがログに出ないことを確かめるテストがある
- `dimap` の 2 つの法則と、保存する行の往復の性質テストがある
