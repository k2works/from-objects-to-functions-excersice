# ADR-031 失敗を自前の enum で表し、エラー用のクレートを入れない

日付: 2026-09-29

## ステータス

2026-09-29 提案されました

## コンテキスト

第 7 章で失敗の表し方を作り直します。**3 対象で共通の主題**ですが、Rust だけ事情が違います。

| 対象 | この章で作ったもの |
| :--- | :--- |
| Kotlin | `Outcome` 型を自作（[ADR-006](ADR-006-outcome-port-type.md)） |
| なでしこ3 | 結果辞書を自作（[ADR-018](ADR-018-outcome-dict-port.md)） |
| **Rust** | **`Result` が言語にある。作るものが無い** |

作るものが無くても、決めることは残ります。**`Result<T, E>` の `E` を何にするか**です。

### 測った条件（先に決めた）

1. 空のクレートから始める（依存 1 行 = 自分だけ）
2. `cargo add` したあと `cargo clean` してからビルドする
3. 各案とも同じ手順。レジストリのキャッシュは共有

**Unit 3 で「1 回しか測っていない値を比較に使い、誤った推奨を出した」ので、条件を先に書きました。**

### 結果

| | 自前の `enum` | `thiserror` | `anyhow` | 文字列 |
| :--- | :--- | :--- | :--- | :--- |
| 依存クレート | **+0** | **+10** | **+1** | +0 |
| 依存のビルド（clean から） | **0 秒** | **12.29 秒** | **2.15 秒** | 0 秒 |
| 失敗を `match` で分けられるか | **できる** | できる | **できない** | できない |
| 与えるもの | 何も | `Display` の導出・`#[from]` | 型を 1 つに潰す・文脈の積み上げ | 何も |

`#[from]` が何を省くのかも確かめました。**これ 1 つです。**

```rust
impl From<DomainError> for HttpError {
    fn from(e: DomainError) -> Self {
        HttpError::Domain(e)
    }
}
```

これを書けば `?` が経路をまたいで変換します（`spikes/error-crates/`）。

## 決定

**失敗を自前の `enum ZettaiError` で表します。エラー用のクレートを入れません。**

1. 第 6 章の `Rejected` を育てて `ZettaiError` にする。**「断られた」と「見つからない」を 1 つの型にする**
2. **理由は値を持つ**（`ListNotFound { user, list_name }`）。「無い」だけを返さない
3. 境界をまたぐときは `impl From` を手で書く
4. `Display` は**必要になるまで書かない**。いまは状態コードに写すだけで足りる
5. ポートの戻り値を `Option<T>` から `Result<T, ZettaiError>` に変える

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `thiserror` | **依存 +10・ビルド +12.29 秒。** 与えるのは `Display` の導出と `#[from]` で、`#[from]` の中身は 1 つの `impl From`。`just check` の上限 20 秒に対して対価が重い（第 3 章の `cucumber`・第 5 章の `proptest` と同じ基準） |
| `anyhow` | 軽い（+1・2.15 秒）が、**型を 1 つに潰すので `match` で分けられない**。第 6 章で理由を型にした効きめ（HTTP 側の `match` が漏れを止める）を捨てることになる |
| 文字列 1 つ | なでしこ3 版が抱えた問題（`空` が 3 つの意味を持つ）に自分から戻る |
| `Option` のまま | 「無い」としか言えない。**誰のどのリストが無いかが分からない** |

## 影響

- **`Result` が `#[must_use]` なので、戻り値を捨てると止まります。** `Option` は止まりません。**この変更で、失敗を握りつぶしていた箇所が 1 つ見つかりました**
- 理由を足すと、状態コードに写す `match` が止まります（実際に止まりました）
- 波及は段階的に見えます。**一度に全部は見えません**

| 段 | 落ちた件数 |
| :--- | :--- |
| ドメインのシグネチャを 3 つ変える | 4 件 |
| ドメインのテスト | 7 件 |
| HTTP のクレート | 10 件 |

- ドメインのクレートは**依存 0 のまま**です（[ADR-027](ADR-027-crate-boundary.md)）

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **`Display` が要る場面** | ログに出すときに要ります。第 12 章（監視）で判断します。**そのとき `thiserror` を測り直します** |
| 理由が増え続けたとき | いまは 3 つです。**10 を超えたら、層ごとに型を分けるかを判断します** |
| 外部クレートのエラーを包むとき | 第 9 章で `postgres` のエラーが入ります。**`impl From` を書くか、変換を境界に置くかをそのとき決めます** |
| `?` の使いどころ | いまはハブの中だけです。増えたときに方針を決めます |

## コンプライアンス

- `Cargo.toml` にエラー用のクレートが現れないこと
- 失敗を `Option` で表す箇所が、ドメインとポートに無いこと
- `ZettaiError` を受ける `match` にワイルドカードが無いこと
