## 満足条件

### Intent

> **副作用を `IO` の値にし、型クラスを標準の語彙として使うエコシステムで、同じ 13 章を辿ったとき、設計は何を得て何を手放すのか。** Kotlin FP 版（Arrow）は「ライブラリへ委ねるほど意図は明確になるか」を問い、Flix 版は副作用を言語の効果として追跡した。Scala は、ライブラリが与える形で同じ問いを問い直す。

4 つの問いに分けて立てました（[執筆計画](../article/outline.md)）。

1. 副作用を `IO` の値にすると、核と殻の分離は型で守られるか
2. 自作した抽象は、Cats のものと何が違うか
3. `IO` の遅延評価は、テストの書き方をどう変えるか
4. `Resource` は、後始末を型で保証するか

答えは [第 13 章](../article/zettai/scala/chapter13.md) にあります。

## リスクと、実際に起きたこと

| 計画で挙げたリスク | 実際 |
| :--- | :--- |
| ライブラリの版の組み合わせが動かない | Scala 3.3.9、Cats Effect 3.7.1、http4s 0.23.38、doobie 1.0.0-RC13 の組み合わせで、全テストが通った。http4s は 1.0 がマイルストーンのため、安定版の 0.23.38 を使った |
| doobie が 1.0 の RC のまま | RC13 を使った（ADR-051）。パッケージ名が `doobie` から `org.typelevel.doobie` に変わっていて、`import` が通らなかった |
| Nix の `scala` devShell に JDK が明示されていない | `jdk21` を明示し、Docker 上の Nix で JDK 21.0.9 と `sbt test` を確かめた |
| sbt の初回起動が遅い | 初回の所要時間は**測っていない**。CI では `setup-java` の `cache: sbt` を使った |
| Cucumber が Scala 3 で使えない可能性 | Maven Central に `cucumber-scala_3` があることは確かめた。`IO` と組み合わせて動かすことは試さず、関数値のケースクラスを採った（ADR-049） |
| `IO` の型は `IO` の外の副作用を止めない | 第 1 章で `println` が通ることを確かめ、第 12 章で、ログを外から包む設計で守った。第 13 章で総括した |
| 型クラスの記法が読者に重い | 初出で用語を説明し、タグレス・ファイナルは採らなかった |
| ライブラリを使うほど、自作した抽象との対比が薄まる | 第 5・8・11・12 章で、Cats のものと突き合わせた。置き換えたものと、置き換えなかったものを第 13 章に表にした |

計画に無かったが起きたことは、[リリース完了報告書](release_report-scala-1.0.0.md) にあります。
