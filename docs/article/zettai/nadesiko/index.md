# Zettai — なでしこ3 版

ToDo リストアプリケーション **Zettai** を TDD で一から作りながら、オブジェクト指向から関数型へ設計を移していく連載の**なでしこ3 版**です。

**想定読者は、動的型付けの言語で設計を良くしていきたい開発者です。** なでしこ3 の経験も関数型プログラミングの経験も要りません。日本語プログラミングに触れたことがなくても読めます。

## この版の焦点

[Kotlin 版](../kotlin/index.md) と同じ 13 章を、**型システムを持たない言語**で辿り直します。なでしこ3 には次がありません。

- 型注釈もコンパイル時の型検査もない
- クラス構文も、独自の型を定義する仕組みもない
- 代数的データ型（直和型）を表す手段がない
- モナドを書くための記法（`do` 記法や `for` 内包表記）がない

それでも同じ設計に到達できます。**Kotlin 版でコンパイラが担っていた保証を、この版ではテストが肩代わりします。** 13 章を読み終えると、「型で保証する」と「約束とテストで保証する」の違いが、具体的なコードの形として分かります。

> **これは教材です。** 認証・認可、HTML エスケープ、CSRF 対策、スナップショットは扱いません。そのまま本番で使わないでください。

## 開発環境

```text
nix develop .#nadesiko
cd apps/nadesiko/zettai
make check
```

第 2 章以降はアプリケーションを起動できます。

```text
make run
```

| [1](chapter01.md) | 新しいアプリケーションを準備する | 題材の設定と、テストフレームワークの無い言語でテストに開発をガイドさせる前提を置く |

| [10](chapter10.md) | コンテキストを読み込み、コマンドを処理する | 文脈を受け取る関数でトランザクション相当の処理をまとめる |
| [11](chapter11.md) | アプリカティブによるデータバリデーション | 複数のエラーを集約する検証を合成する |
| 12 | 監視と関数型 JSON | 構造化ロギングと辞書 ⇄ JSON の双方向変換を扱う |

代数構造は第 5・7・9・11・12 章で 1 つずつ出てきます。型が無いので、**構造そのものではなく「その構造が守る約束」をテストで確かめる**形になります。
