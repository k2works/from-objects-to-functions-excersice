## 判断と学び

### 1. ゲートを減らして、止まった

**3 箇所から 1 箇所に減らして、1 / 1 で同期停止しました。累計 9 / 9（100%）です。**

これまで 2 回続けて「停止したから減らさない」としてきました。**今回が初めて減らす方向に動かした Unit**です。

| Unit | エントロピー評価 | ゲート | 停止 |
| :--- | :--- | :--- | :--- |
| Unit 1 | リスク・仮定が HIGH | 3 | 3 / 3 |
| Unit 2 | 構造が MED | 2 | 2 / 2 |
| Unit 3 | 構造・仮定が HIGH | 3 | 3 / 3 |
| **Unit 4** | **5 軸すべて LOW** | **1** | **1 / 1** |

**ゲートの密度をエントロピー評価で決める運用が、減らす側でも成り立ちました。** なでしこ3 版の 41 箇所中 1 回に対し、ここまで **9 箇所中 9 回**です。

### 2. 言語が与える章でも、判断は残った

本 Unit の仮説でした。**残りました。**

| 章 | 言語が与えたもの | それでも残った判断 |
| :--- | :--- | :--- |
| 第 6 章 | `enum`・`match` の網羅 | **どこまで守られるか**。守られない穴が 2 種類あった |
| 第 7 章 | `Result`・`map` | **既製品を入れるか。理由をどう表すか** |

ただし**性質は変わりました**。2 対象の第 6・7 章は「何を作るか」の判断でした。Rust では「**何を作らないか**」と「**与えられたものがどこまで守るか**」の判断になっています。

### 3. 「lint で守れる」と書こうとして、実機が訂正した

第 6 章の話です。`match` の網羅をワイルドカードが無効にする問題に、`clippy::wildcard_enum_match_arm` という lint があります。

**「これで守れる」と書こうとして、確かめたら守れませんでした。**

| 形 | lint |
| :--- | :--- |
| 単体の `enum` を直接 `match` | **発火する** |
| **組（`(State, Command)`）** | **発火しない** |
| `Option<&T>` ごし | 発火しない |

**遷移表はまさに組で受ける形です。** 守ってほしいところで効きません。

結果として、なでしこ3 版が「コンパイラが無いから数える」と書いたのに対し、Rust 版は「**コンパイラがあっても数える。守る範囲が違うから**」になりました。

### 4. `Result` が `must_use` で、既にあった欠陥を見つけた

`Option` を `Result` に変えたら `just check` が落ちました。

```text
error: unused `std::result::Result` that must be used
```

受け入れテストの経路で、**項目を足した結果を捨てていました**。足せなくても黙って通っていたということです。

`Option` には `#[must_use]` が付いていません（実機で確認）。**型を変えたことが、既存の欠陥を 1 つ見つけました。** 2 対象には起こりえない出来事です。

### 5. 波及を数えた。一度に全部は見えない

契約を先に変えて数えました（なでしこ3 版 Unit 4 と同じ手）。

| 段 | 落ちた件数 |
| :--- | :--- |
| ドメインのシグネチャを 3 つ変える | 4 件 |
| ドメインのテスト | 7 件 |
| HTTP のクレート | 10 件 |

**cargo はクレート単位で止まる**ので、ドメインが通るまで HTTP 側は出てきません。なでしこ3 版は「テストがある箇所しか分からない」代わりに一度に出ました。**どちらも全体像は一度に見えません。理由が違います。**

### 6. 計算と実測が初めて一致した

ファンクタ則の検出率です。

```text
隠れた欠陥の検出 50 / 200    （期待値 50・σ 6.12）
```

Unit 3 では計算を 1 度間違えて実測に直されました。今回は**見逃しのある壊し方を先に設計してから計算**したので、一致しました（Unit 3 Try 2）。

### 7. 段階を切ったら、初回だけ上限を超えた

3 つめの段階（`zettai-step3-*`）を切りました。

| | 初回 | 定常 |
| :--- | :--- | :--- |
| devShell 外 | **36.25 / 23.26 秒（上限 20 秒を超える）** | 6.37〜8.50 秒 |
| devShell 内 | — | 5.33〜6.89 秒 |

**Unit 3 で「初回の値を比較に使った」失敗をしたので、初回と定常を分けて記録しました。**

定常は上限内ですが、段階が増えるごとに伸びています（4.97 → 6.37〜8.50 秒）。**段階 5 つで上限に当たる見込みです。**

### 8. ADR どうしがぶつかった

[ADR-029](../adr/ADR-029-cutting-a-step.md)（段階を切る判断はゲートに載せる）と、[リリース計画](release_plan-rust.md) のゲート規約 1（選択肢と数字を添えられないものはゲートにしない）がぶつかりました。

第 7 章は基準で答えが決まるので、選択肢が立ちません。**規約 1 を優先し、ADR-029 に追記しました**（基準で決まらないときだけゲートに載せる）。

**計画の段階で気づいて、人に判断を仰いでいます。** 実装中に気づいていたら、どちらかを黙って破っていました。
