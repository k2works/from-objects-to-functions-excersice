# ADR-058 TypeScript FP 版は依存を、関数の引数でハブに渡す

日付: 2026-11-28

## ステータス

2026-11-28 承認されました（Unit 3 のゲート ③ で、人が推奨の案 A を選びました）

## コンテキスト

第 4 章で、ドメインの入口 `ToDoListHub` を新設します（[ドメインモデル設計](../design/domain-model.md)）。ハブは、リストを取得する依存を受け取り、web はハブの操作だけを呼びます。この依存を、何の形で渡すかを決めます。

この版の主題の 1 つは、依存を `Effect<A, E, R>` の `R` に載せると、設計のどこが型で守られるかです。確かめる仮説は「`R` に依存を載せると、差し替えの漏れが型で分かる」でした。

### 先に確かめたこと

同じ処理を 3 通りに書きました。条件と全結果は、[Unit 3 の Bolt 計画](../development/iteration_plan-typescript-fp-3.md)の「ゲート ③ の比較結果」にあります。

| 案 | 形 | 行数（ハブ・web・組み立て・差し替え） |
| :--- | :--- | :--- |
| A（採用） | 依存を関数の型にして、引数でハブに渡す | 35 |
| B | 依存を `Context.Service` にし、`Effect.provideService` で与える | 43 |
| C | 依存を `Context.Service` にし、`Layer` で与える | 41 |

- **提供忘れは、3 案とも型検査で止まりました。** A は引数の不足（`TS2554`）、B・C は `R` が残ることによる型エラーと、Effect の診断 `missingEffectContext` です。B・C の診断は、足りない依存の名前を示しました
- **仮説は成り立ちました。ただし、この比較では、漏れの検出に `R` の利点は見られませんでした**
- B・C は、実行や接続の境界に渡す場所で、初めてエラーになりました
- 依存を 1 つ増やしたとき、ハブのほかに直したファイルは、A が 2、B・C が 3 でした。B・C は、web の戻り値の型に `R` を明示していました
- C で要求ごとに `Layer` を与えると、3 回の要求で 3 回組み立てられました。一度組み立てて渡すと 1 回でした

比較は、依存が 1 つの小さな実装で行いました。B・C の形では、サーバーを起動していません。

## 決定

1. **ハブは、依存を関数の引数で受け取って作る値にする。** `makeHub(fetch)` が `ToDoListHub` を返す
2. **web は、ハブを受け取る。** `makeApp(hub)`。取得の依存の型を、web は読み込まない。読み込みの検査で固定する
3. **依存は `R` に載せない。** 第 4 章の `App` の型は、`Effect<Response>` のまま変えない
4. **提供忘れと、ハブの代わりに依存を渡す誤りは、`@ts-expect-error` のテストで固定する**

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| B | いまの依存は値が 1 つで、行数と型の記述が増えるのに対し、漏れの検出で差が見られなかった |
| C | B と同じ理由。加えて、`Layer` を組み立てる場所を決める必要がある。いまの依存には、組み立ても後始末も無い |

[執筆計画](../article/outline.md)の「ライブラリを見せるための抽象は増やさない」という方針にも合わせます。3 案の比較は第 4 章に書き、`R` を使う形も読者に示します。

## 影響

### ポジティブ

- 依存が、普通の引数として読める。テストは関数を渡すだけで差し替えられる
- `App` の型、`node:http` への接続、受け入れテストの経路の形を変えずに済む

### ネガティブ

- この版の主題である `Effect<A, E, R>` のうち、`R` は、当面は本体のコードに現れない（`Scope` を除く）
- 組み立てる場所が、依存の組み合わせを自分で持つ。依存が増えると、引数も増える
- **見込み（確かめていない）:** 第 9 章の接続の寿命や、第 10 章のトランザクションの文脈では、`R` と `Layer` が役立つ可能性がある。その時点で選び直すと、ハブと組み立てを書き換えることになる

## コンプライアンス

- web が、取得の依存の型を持つファイルを読み込まないことを確かめるテストがある
- 依存の提供忘れが、`@ts-expect-error` のテストで固定されている
- 第 9 章と第 10 章の ADR で、この決定を続けるかを記録する
