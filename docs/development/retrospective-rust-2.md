## Problem（問題）

| # | Problem | 何が起きたか | 原因 |
| :--- | :--- | :--- | :--- |
| 1 | **計画の順序が間違っていた** | 2-1.2（CI）が 2-1.3（ハンドラ）より前だった。動かないコードで CI を測っても意味が無い | **ステップ間の依存を計画に書いていない。** 番号順に並べただけだった |
| 2 | **持ち込みを 2 回続けて送った** | 「段階を切る手順」と「カバレッジの下限」を Unit 1 → Unit 2 → Unit 3 と送った | どちらも「段階が増える／ドメインが育つ」が前提で、**Unit 2 では前提が揃わないと分かっていた**。計画時に Unit 3 へ直接送るべきだった |
| 3 | **アサーションを 2 度書き直した** | `Vec<String>` と `&[&str]` の食い違いを、無意味なヘルパ関数で回避しようとした | **型の食い違いを読まずに手を動かした。** エラーメッセージは最初から答えを書いていた |
| 4 | **新規 ADR に `generated` が付かなかった** | `gulp okf:check` の WARN で気づいた | `apply-okf` を `--changed` で回したが、新規ファイルが拾われなかった |
| 5 | **ADR-015 のドリフトが 3 対象目でも出た** | 第 3 章の変更で第 1・2 章の記事が落ちた | 段階の区切りが 4 章ごとなので、**構造上必ず起きる**。規則はあるが、起きること自体は防げない |

Problem 1 と 2 は、どちらも**計画の書き方**です。

Problem 3 は Unit 1 Try 1（主張はテストで確かめてから書く）の裏返しでした。**エラーメッセージを読まずに手を動かしています。**
