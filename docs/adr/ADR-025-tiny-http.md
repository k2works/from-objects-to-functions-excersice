# ADR-025 HTTP クレートに tiny_http を採用する

日付: 2026-09-28

## ステータス

2026-09-28 提案されました

## コンテキスト

第 2 章でウォーキングスケルトンを通すために、HTTP クレートを 1 つ選びます。

この選定は [ADR-024](ADR-024-no-async.md)（async の採否）と連動します。tokio 必須のクレートを選ぶと、その時点で async が確定するためです。

### 3 候補で同じハンドラを書いた

「`/todo/{user}/{list}` で ToDo リストを 1 つ返す」ハンドラを 3 つのクレートで書き、実際に応答することを確かめました。

| 候補 | tokio 必須 | 依存クレート数 | 行数 | ビルド時間 | 応答 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`tiny_http`** | 不要 | **5** | 15 | **7 秒** | OK |
| `rouille` | 不要 | 123 | 14 | 58 秒 | OK |
| `axum` | 必須 | 61 | 13 | 70 秒 | OK |

**行数はほぼ同じでした。** 差が出たのは**依存クレート数**（5 / 123 / 61）と**ビルド時間**（7 / 58 / 70 秒）です。

ビルド時間は `just check` の NFR（20 秒以内）に直接効きます。

## 決定

**`tiny_http` を採用します。**

1. ルーティング機構は使わない（`tiny_http` に無い）。**パスの分解を自前で書く**
2. `Cargo.toml` の依存は最小に保つ

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `rouille` | `router!` マクロでパスパラメータを取り出せるのは楽だが、**依存が `tiny_http` の 25 倍**（123 対 5）で、ビルドが 8 倍かかる。得るものはマクロ 1 つ |
| `axum` | 実務で最も使われるが、**tokio 必須**なので [ADR-024](ADR-024-no-async.md) と両立しない |
| `hyper` を直接使う | tokio 必須。同上 |
| 標準ライブラリの `TcpListener` だけで書く | HTTP のパースを自前で書くことになる。**連載の主題は HTTP の実装ではない** |

## 影響

- **ビルドが速く保てます。** `just check` は 2〜3 秒、`just check-all`（カバレッジ込み）は 5〜8 秒です
- **パスの分解を自前で書きます。** なでしこ3 版と同じ形になり、**第 2 章「矢印で設計する」の題材が 2 対象と揃います**（フレームワークがルーティングを隠さない）
- 依存が 5 クレートなので、`Cargo.lock` を読んで何が入っているか把握できます

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| **ルーティング** | 自前です。パスを `split('/')` して `match` します。パスパラメータの型変換もありません |
| **ミドルウェア** | ありません。第 12 章のログはハンドラの呼び出し側に置きます |
| **同時接続** | `tiny_http` はスレッドプールで捌きます。[ADR-024](ADR-024-no-async.md) の制限がそのまま当てはまります |
| **HTTPS** | 扱いません（教材） |

## コンプライアンス

- `Cargo.toml` の HTTP 関連の依存が `tiny_http` だけであること
- ルーティングがドメインに漏れないこと（第 3 章で境界を引く）
