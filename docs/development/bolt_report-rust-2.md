## 判断と学び

### 1. 承認ゲートが 2 / 2 で同期停止した

Unit 1 が 3 / 3、Unit 2 が 2 / 2 で、**累計 5 / 5（100%）**です。3 対象を通した累計は 46 箇所中 6 回になりました。

止まった 2 箇所は、どちらも**選択肢と数字**を添えています。

| ゲート | 添えた数字 | 決定 |
| :--- | :--- | :--- |
| CI に Nix を入れるか | 525 秒 対 17 秒（同じコミットで実測） | **入れない** |
| 境界をクレートで分けるか | エラー 0 件 対 コンパイル停止、ビルド時間は同じ | **クレートで分ける** |

**どちらも「両方作って測った」**のが効きました。CI は 2 案を同じコミットに並べて走らせ、境界は両方の構成を作って**わざと境界を破るコードを書いて**確かめました。

### 2. 境界検査を 1 行も書かなかった

3 対象で初めてです。

| 対象 | 境界を守るために書いたもの |
| :--- | :--- |
| Kotlin | `DomainBoundaryTest`（import を検査） |
| なでしこ3 | `boundary_test.nako3`（7 ファイル × 5 項目 = 35 件） |
| **Rust** | **無し** |

`Cargo.toml` の `dependencies` が依存の一覧そのものなので、**書いていない相手を呼ぶとコンパイルが止まります。**

```text
error[E0433]: failed to resolve: use of unresolved module or unlinked crate `zettai_step1_http`
```

**足し忘れが起きません。** なでしこ3 版は章が進むごとに検査の項目が増え（第 2 章 1 項目 → 第 12 章 5 項目 × 7 ファイル）、第 4 章で一覧への足し忘れが起きかけました。

**ビルド時間は変わりませんでした**（どちらも 3 秒）。増えたのは `Cargo.toml` 1 個だけです。

### 3. CI の二重管理を、検査で押さえた

ゲート 1 で案B（`just` を通さず `cargo` を直接呼ぶ）を選びました。**代償は検査の定義が `justfile` と workflow の 2 か所に分かれること**です。

段を足したとき片方だけ直すと、**CI だけ古い検査で通り続けます。**

そこで `ops/scripts/check_rust_ci_parity.py` を書きました。`justfile` の `check-all` が呼ぶ子レシピの `cargo` コマンドと、workflow の `run:` を突き合わせます（`{{cov_min}}` は展開してから）。

**わざとずらして落ちることを確認済み**で、CI の `parity` ジョブとして回しています（6 秒）。

これはなでしこ3 版 Unit 5 の学び「**懸念を書くだけでは防げない。検査が止める**」の適用です。

### 4. 既製品を調べて、寄せないと決めた

受け入れテストの枠組みで `cucumber` を調べました。

| 項目 | 現状 | `cucumber` を入れると |
| :--- | :--- | :--- |
| 依存クレート数 | 6 | **127** |
| ビルド時間 | — | **+92 秒** |

`just check` の上限 20 秒を単独で超えます。与えるのは Gherkin ですが、**必要なのは経路の差し替えでトレイト 1 つで足りました。**

第 3 章第 5 節（Kotlin 版では「DDT を Pesticide に変換する」）で、**3 対象の結論が 3 つとも違いました。**

| 対象 | この節でしたこと |
| :--- | :--- |
| Kotlin | 自作 → ライブラリに寄せた |
| なでしこ3 | 自作のまま（寄せる先が無い） |
| Rust | **調べて、寄せないと決めた** |

**同じ節・同じ目的で結論が 3 通りに分かれた**のは、この連載で初めてです。

### 5. 所有権に押されたのは 1 件だけだった

第 2 章の仮説は「所有権は縦串の段階では邪魔にならない」でした。**ほぼそのとおりでした。**

押されたのは 1 件で、受け入れテストの一時値の借用（E0716）です。**押された先は読みやすい形**（「取り出す」と「見る」が 2 行に分かれる）でした。

なでしこ3 版で 5 回起きた「制約に押されて、押された先が正しかった」と同じです。**制約の出どころが型でも型の不在でも同じ**という仮説の 1 件目が立ちました。

型そのものの摩擦は別に 1 件ありました。**`Vec<String>` と `&[&str]` が比べられない**（E0308）ことです。1 行増やして揃えました。**型が多いことの代償**で、2 対象には無い種類です。

### 6. ADR-015 の「段階の中のドリフト」が Rust でも出た

第 3 章でクレートを分けたら、**第 1 章と第 2 章の記事が `check_article_code.py` で落ちました。**

なでしこ3 版では Unit 4 で初めて出た問題が、**Rust 版では Unit 2 で出ました。** 段階（workspace メンバー）を第 4 章まで増やさないので、第 1〜3 章が同じ段階にいるためです。

[ADR-015](../adr/ADR-015-step-directories.md) の規則どおりに処理しました。

| 箇所 | 処理 |
| :--- | :--- |
| 第 1 章の `workspace.members` | **最終形に直す**（章の主題ではない） |
| 第 2 章の 1 経路のシナリオ | **`ignore` を付け、第 3 章で置き換わると書く**（その形が章の主題） |
| 第 3 章の「第 2 章はこうだった」の引用 | 同上 |

**規則が既にあったので迷いませんでした。** 3 対象目にして、過去の対象の ADR がそのまま効いた例です。

### 7. 計画の順序を 1 つ入れ替えた

計画では 2-1.2（CI）が 2-1.3（ハンドラ）より前でした。**動かないコードで CI を測っても意味がない**ので、Green にしてから CI を作りました。

**計画の誤りです。** 「CI を作る」は「動くものがある」ことが前提なのに、その依存を計画に書いていませんでした。
