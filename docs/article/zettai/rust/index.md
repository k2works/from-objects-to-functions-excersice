# Zettai — Rust 版

ToDo リストアプリケーション **Zettai** を TDD で一から作りながら、オブジェクト指向から関数型へ設計を移していく連載の **Rust 版**です。

**想定読者は、所有権のある言語で関数型の設計をしたい開発者です。** Rust の入門的な説明はしません。所有権・借用・ライフタイムの基礎を知っている前提で、**それが設計をどこへ押すか**だけを書きます。

## この版の焦点

[Kotlin 版](../kotlin/index.md) と [なでしこ3 版](../nadesiko/index.md) と同じ 13 章を、**言語が多くを与える側**から辿り直します。

| | Kotlin | なでしこ3 | **Rust** |
| :--- | :--- | :--- | :--- |
| 型 | あり | なし | あり |
| 関数型の道具 | あり | なし | あり |
| `Outcome` 相当 | **自前で作る** | **辞書で作る** | **`Result` が言語にある** |
| 代数的データ型 | `sealed interface` | 無い | `enum` |
| テストの土台 | JUnit + Strikt | **自作する** | **`#[test]` が言語にある** |

なでしこ3 版は「何も無い」側の極でした。この版は反対側です。**Kotlin 版が第 7 章で自前実装したものが、最初からあります。**

代わりに、2 対象に無かった制約が入ります。**所有権・借用・ライフタイム**です。

この版で問うのは 2 つです。

1. **言語が与えるものが増えたとき、章の主題はどう変わるか。** 与えられたものを使う判断も、作る判断と同じだけ記録に値するはずです
2. **型の側の制約も、設計を押すのか。** なでしこ3 版では「型が無い」制約が 5 回設計を押し、5 回とも素直な方向でした。所有権でも同じことが起きるなら、**制約の出どころが型でも型の不在でも同じ**という話になります

> **これは教材です。** 認証・認可、CSRF 対策、スナップショットは扱いません。そのまま本番で使わないでください。

## 開発環境

```text
nix develop .#rust
cd apps/rust/zettai
just check
```

| 項目 | 内容 |
| :--- | :--- |
| rustc | 1.91.1 |
| cargo | 1.91.0 |
| 検査 | `just check`（`fmt` + `clippy` + `test`） |
| テスト | 組み込みの `#[test]`（自作しない） |
| HTTP | 第 1 章で選定する |
| 永続化 | PostgreSQL（第 9 章） |

## 章の目次

| 章 | タイトル | この章の焦点 |
| :--- | :--- | :--- |
| [1](chapter01.md) | 新しいアプリケーションを準備する | テストの土台が言語にある場合に、第 1 章で何をするのか |
| [2](chapter02.md) | 関数を使って HTTP を扱う | HTTP クレートを 1 つ選び、縦串を通す。所有権との初遭遇 |
| [3](chapter03.md) | ドメインの定義とテスト | 受け入れテストを抽象化し、クレートの分割で境界を引く |
| 4 | ドメインとアダプタのモデリング | 関数型 DI を所有権のもとでどう表すか |
| 5 | イベントで状態を変更する | 状態変換のクロージャ合成とモノイド |
| 6 | コマンドを実行してイベントを生成する | `enum` + `match` の関数型ステートマシン |
| 7 | 関数型手法によるエラーハンドリング | `Result` を使う。**自前で作らない判断を記録する** |
| 8 | ファンクタを使ってイベントを射影する | 射影でクエリ側を分離し、CQRS に到達する |
| 9 | モナドによる安全なデータ永続化 | PostgreSQL 永続化とモナド則 |
| 10 | コンテキストを読み込み、コマンドを処理する | 境界とライフタイム |
| 11 | アプリカティブによるデータバリデーション | 複数のエラーを集約する型を自前で作る |
| 12 | 監視と関数型 JSON | 構造化ログと双方向変換。プロファンクタ |
| 13 | 関数型アーキテクチャの設計 | **3 言語**を対比する |

代数構造は第 5・7・8・9・11・12 章で出てきます。2 対象と同じく、**法則を性質テストで確かめ、壊して検出率を測ります。**

## 既知の制約

踏んだ制約は `apps/rust/zettai/README.md` に集めています。**Unit 1 から置いています**（なでしこ3 版では Unit 6 になってから作り、それまでに同じ制約を 3 回踏みました）。

一覧は 3 つに分かれています。

- 言語・処理系の制約
- **所有権に押された箇所**（第 13 章で「設計の改善」と「回避しただけ」に仕分ける）
- **`clippy` に押された箇所**（同じく第 13 章で仕分ける）
