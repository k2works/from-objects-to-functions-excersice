## Problem

- 一時スクリプトの引用で、またつまずきました。この環境では、コマンド中の連続したバックスラッシュが畳まれ、Kotlin の文字リテラルや、正規表現の後方参照が壊れました（`import` 文に制御文字が混ざった）。ファイルに書いて実行する Try は守りましたが、ファイルの内容そのものが壊れる原因までは考えていませんでした。
- Gradle を誤ったディレクトリで実行し、出力が空だったために「エラーなし」と読みかけました。`grep` で絞った出力は、`BUILD` の行が無いときを失敗として扱うべきでした。
- `sealed interface` を別の package から継承できないことを、実装してコンパイルして初めて知りました。循環を断つ設計を、先に型の置き場所から考えるべきでした。
- テンプレート関数は、テストと実装を同時に書いてから走らせました。Red を確認していません。実装が小さくても、TDD の手順を省いたことに変わりはありません。
- 受入条件の表の文言（「同じ結果」）が、テストの実態（store ごとに期待を分けた）と食い違っていました。表を計画で先に書き、実装で分かったことを表に戻さなかったためです。
- テストの文字数の数え間違い（`<b>/` は 4 文字）で、1 回無駄に失敗しました。期待値は、数えるのではなく、入力から導く書き方が安全でした。
- 記事に書いた経緯（「4 件とも失敗」）が、履歴から裏付けられませんでした。実装とテストを 1 つのコミットに入れたためです。
- 受入条件の「高・中の残件がない」は、中の持ち越しが 5 件あり、満たせませんでした。レビューの中を全部直す範囲は決めていませんでした。

- 型を別の package に移すときは、`sealed` の制約（同じ package と module）を先に確かめます。
- 小さな関数でも、テストを先に走らせて Red を確認します。確認したことを、記事に書けるよう、コミットを分けます。
