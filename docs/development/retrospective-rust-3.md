## Problem（問題）

| # | Problem | 何が起きたか | 原因 |
| :--- | :--- | :--- | :--- |
| 1 | **人に誤った推奨を出した** | 「初回 24.77 秒で上限 20 秒を超えるから `bin` を減らす」と勧めた。実際は依存クレートの初回ビルドで、段階とは関係が無かった | **1 回しか測っていない値を、比較の根拠に使った。** 条件（キャッシュの状態）を揃えていない |
| 2 | **分布の計算を間違えた** | 「順序を入れ替えると 3/16 見逃す」と計算した。実測は 200 / 200 | `compose(f, g)` が `g(f(x))` であることを取り違えた。**定義を確かめずに確率を計算した** |
| 3 | **`git stash` を中身を見ずに落とした** | ゲート 1 の記録と Red のテストを消した。書き直した | **`stash` したときと `drop` したときで、入っているものの把握が違っていた。** 作業ツリーを片付ける目的で stash し、そのまま落とした |
| 4 | **TDD の順序が崩れた箇所がある** | ハブの実装を書いてからテストを書いた（3-1.4） | 受け入れシナリオが Red だったので「Red は立っている」と流した。**単体の Red を立てていない** |
| 5 | ADR を 1 つ減らした | 計画は 3 新設。実際は 2 新設 + 1 追記 | 計画時に「既存 ADR への追記で足りるか」を見ていない。**害は無いが、計画の精度の問題** |

**Problem 1 と 2 は同じ形です。** どちらも**計算・計測を確かめずに主張した**もので、どちらも**実測が直しました**。

Problem 1 は人の判断を一度誤らせています。**測った数字をゲートに載せる前に、条件が揃っているかを確かめる**必要があります。
