# ADR-052 Scala 版は JSON と型付きのログ記録を自作し、circe と log4cats を入れない

日付: 2026-11-02

## ステータス

2026-11-02 承認されました

## コンテキスト

第 12 章で、ログと JSON の手段を決めます。

| 対象 | ログ | JSON |
| :--- | :--- | :--- |
| Kotlin | 自作 | 自作（[ADR-012](ADR-012-own-json-converter.md)） |
| Kotlin FP | decorator と型付きの `LogRecord`（[ADR-045](ADR-045-logging-as-decorator-with-typed-record.md)） | JSON の木 |
| Rust | `tracing` | `serde` |
| Flix | 標準の `Logger` 効果と型付きの `LogRecord` | 自作（[ADR-048](ADR-048-flix-logger-effect-and-own-json.md)） |

Scala には、標準的な選択肢があります。JSON は circe、ログは log4cats です。どちらも Cats Effect と相性がよく、広く使われています。

### 先に確かめたこと

| 項目 | 結果 |
| :--- | :--- |
| 標準に JSON があるか | **無い**（Scala の標準ライブラリに JSON は含まれない） |
| circe の安定版 | Maven Central の最新は 0.15.0-M1（マイルストーン）。安定版の 0.14 系があるかは、**この決定のために確認していない** |
| ドメインの関数にログを足すのを型が止めるか | **止めない。** 第 1 章で、`println` を入れても `sbt compile` が通ることを確かめた。Flix の `Logger` 効果のような守りは、Scala には無い |
| 自作の量 | JSON が 141 行（木、書き出し、読み込み）、ログの記録が 72 行、ログを足すデコレータが 104 行 |

### 試していないこと

- circe と log4cats は**試していない。** 採らなかったのは、試した結果ではなく、下の理由による判断である
- circe の自動導出で `LogRecord` を書き出したとき、載せる欄が型で決まるかどうか

## 決定

1. **JSON は自作する。** 木（`JsonTree`）、文字列への書き出し、文字列からの読み込み、型との双方向の束（`Converter`）を作る。読めないものは例外ではなく失敗の値にする
2. **ログの 1 行は、自作の型 `LogRecord` で表し、JSON の 1 行として書く。** 自由な `Map` は持たない
3. **ログは、操作を外から包むデコレータで足す。** ドメインの関数には、ログを足さない。出力先（`LogSink`）はテストが差し替える
4. **ログの出力先が壊れても、処理は止めない。** 想定外の失敗（`IO` の失敗）は、種類だけを記録して投げ直す

### 採った理由

- **載せるものを、型で決められる。** `LogRecord` の 6 つの欄以外は、載せる場所が型にない。項目の説明、イベントの中身、失敗の理由は、書かないという規律ではなく、書けないことで守られる
- **Scala の型はログの混入を止めないので、型で決める範囲を狭く保つ意味がある。** 文字列ベースのログ API（log4cats の `info(String)`）は、何でも載せられる
- **追加の依存が増えない。** ここまでの依存は Cats、Cats Effect、http4s、doobie だけである
- **境界値の往復を、自分のテストで確かめられる。** 学びとして残る

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| circe を入れる | 試していない。載せるものを型で決める方針と、自動導出の相性が未確認。安定版の確認も要る |
| log4cats を入れる | 試していない。文字列ベースで、載せてはならないものを型で止められない |
| `println` で出す | 出力先をテストが握れない。構造化もされない |
| ドメインの関数の中でログを書く | ドメインが出力先を知ることになり、純粋さが崩れる |

## 影響

- JSON の読み書きは、自作のコードの品質に依存する。第 12 章の往復のテスト（境界値、特殊文字、小さな範囲の全パターン）で守る
- 将来、JSON の形が増えたとき（複数の型を扱う、スキーマが変わる）に、circe に移る余地を残す
- 読み込みは再帰降下で書いた。**深くネストした入力でスタックを使い切る**可能性がある。ログの 1 行は浅いので、この題材では問題にならないが、外から来る JSON を読む用途には使わない

### この決定が解かないこと

| 解かないこと | どうするか |
| :--- | :--- |
| 外から来る任意の JSON を読むこと | 自作の読み込みは、ログの 1 行を読む用途に限る。必要になったら circe を使う |
| ログのレベル（debug・info・error）や出力先の切り替え | `LogSink` の差し替えで足りる範囲に留める。必要になったらライブラリを検討する |
| 分散トレースの相関 ID | 第 10 章で挙げた `IOLocal` の使い道。この連載では扱わない |

## コンプライアンス

- `LogRecord` に自由な文字列の欄（`Map` や `String` の message）を足さないこと
- ドメインの関数（`Commands`、`Events`、`Domain`）にログの呼び出しを足さないこと
- 失敗の理由の文字列を、ログの行に載せないこと（`LoggingSuite` で確かめる）
