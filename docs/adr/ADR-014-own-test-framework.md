# ADR-014 なでしこ3 版のテスト基盤を自作し、静的解析は文法検査だけにする

日付: 2026-09-28

## ステータス

2026-09-28 提案されました

## コンテキスト

[ADR-013](ADR-013-cnako3-runtime.md) で cnako3 を採用しました。TDD で進めるにはテストが要りますが、**なでしこ3 にはテストフレームワークがありません**。Unit 1 / ステップ 1-1.0 のスパイクで、土台になる材料と制約が分かりました。

| 事実 | 影響 |
| :--- | :--- |
| 組み込みの表明命令 `【A】と【B】がASSERT等` がある | 比較の土台には使える |
| `変数型確認` がある（`"number"` / `"string"` を返す） | 型の取り違えを実行時に検出できる |
| **`=` も `ASSERT等` も型を区別しない**（`3` と `「3」` が等しい） | 値だけ比べるテストは、型の取り違えを見逃す |
| **cnako3 は実行時エラーでも終了コードが 0** | テストランナーが終了コードで合否を判定できない |
| `1でプロセス終` で終了コードを明示できる | 上の回避策になる |
| **`lint` / `format` のサブコマンドが無い**（`gonako` にはあった） | 静的解析の手段が無い |
| `cnako3 -A`（AST 出力）は文法エラーを標準エラー出力に書く | 文法検査の代わりになる |

型システムが無いため、Kotlin 版でコンパイラが担っていた保証をテストが肩代わりします。テスト基盤が弱いと、連載全体が「通っているのに間違っている」状態を検出できなくなります。

## 決定

**テストフレームワークを自作します。** 加えて**汎用の静的解析は入れず、文法検査だけを `check` に入れます。**

1. `test/helper.nako3` に検証関数 `●(名前と実際と期待で)検証` を置く。**値を比べる前に `変数型確認` 同士を比べる**
2. `●テスト結果報告` が、失敗が 1 件でもあれば `1でプロセス終` を呼ぶ。これでテストランナーが終了コードで判定できる
3. テストランナーは `Makefile` の `test` ターゲットに置き、`test/*_test.nako3` を 1 本ずつ実行して集計する
4. `make lint` は `cnako3 -A` を全 `.nako3` に対して実行し、**標準エラー出力が空でなければ文法エラー**とする
5. `make check` = `lint` + `test`
6. **検証関数自身をテストする**（`test/helper_test.nako3`）。この層だけは組み込みの `ASSERT等` を直に使う
7. フォーマッタは入れない

### 検討した代替案

| 案 | 採らなかった理由 |
| :--- | :--- |
| `ASSERT等` を直接テストに書く | 型を区別しないので、`3` と `「3」` の取り違えを見逃す。型システムの無い言語でこれを見逃すと、連載の主張（約束とテストで保証する）が成り立たない |
| 既存連載（`gonako` 版）の `helper.nako3` をそのまま流用する | 処理系が違い、終了コードの扱いが異なる（`gonako` は非ゼロを返す）。流用すると「失敗しても green」になる |
| JavaScript 側でテストランナーを書く（Jest など） | なでしこ3 で書いた実装をなでしこ3 でテストする、という連載の前提が崩れる。読者が追えなくなる |
| 文法検査も入れない | 動的型付けで、綴りの誤りが実行するまで分からない。実行しない分岐の文法エラーを CI で止められなくなる |

## 影響

- **Unit 1 の作業が Kotlin 版より重くなります。** 検証負荷を 8 から 11 に上げた主因がこれです
- **検証関数が壊れると全テストが嘘をつきます。** だから検証関数自身をテストし、承認ゲートを 1 つ置きました
- **終了コードの扱いが連載の題材になります。** 「テストが失敗したのに green になる」は、型の無い言語で最初に踏む落とし穴です。第 1 章のつまずき節で扱います
- 書き方のブレは人のレビューで吸収します。1 名体制で、整形のブレはまだ問題になっていません

## コンプライアンス

- `3` と `「3」` を比べる検証が**失敗する**こと（`make test` が終了コード 1 を返す）
- 失敗したテストの名前・期待・実際・型が出力から分かること
- `make lint` が文法エラーのあるファイルを検出し、終了コード 1 を返すこと
- 全 Bolt で、辞書を返す関数に契約テストが 1 本あること（第 4 章以降）

## 再検討の条件

時期では区切りません。次のいずれかが起きたら再検討します。

1. 自作の検証関数で書けないテストが出てくる（第 5 章の性質テスト、第 9 章の結合テストが候補）
2. cnako3 に `lint` / `format` が実装される
3. 自作の検査で拾えない種類の問題（未使用コード、バグの兆候）が実際に起きる
4. `make check` が 30 秒を超える
