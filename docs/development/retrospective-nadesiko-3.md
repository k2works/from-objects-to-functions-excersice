## Problem（問題）

| # | Problem | 何が起きたか | 原因 |
| :--- | :--- | :--- | :--- |
| 1 | **承認ゲートが 3 Unit 続けて機能しなかった** | 4 箇所を計画して実績 0 箇所 | 連続実行の指示。今回は計画を書き換えずに済ませたが、**ゲートの意図は満たしていない** |
| 2 | **記事のコード例検査が構造の見落としを見つけた** | 第 5 章で実装を置き換えたら、第 2〜4 章のコード例 7 箇所が落ちた | Kotlin 版は [ADR-007](../adr/ADR-007-module-per-unit.md) でモジュールを Unit の境界で切り、**過去の章のコードが残る**。なでしこ3 版は `src/` が 1 つで、章が進むと消える。**1 言語目の設計判断のうち、移植しそこねたものがあった** |
| 3 | **検査を決め打ちにした（3 Unit 連続）** | 境界検査が `src/domain.nako3` だけを見ていて、`src/events.nako3` が漏れかけた | Unit 1 は言語決め打ち、Unit 2 は対象名の不一致、Unit 3 はファイル決め打ち。**「増えたときに漏れないか」を検査を書くたびに確かめていない** |
| 4 | **人が検証に使った時間を 3 Unit 続けて計測できなかった** | 主指標が 3 回連続で空欄 | Problem 1 の結果 |
| 5 | **ignore マーカーが 7 箇所増えた** | 過去章のコード例を検査の対象外にした | Problem 2 の暫定対応。**章が進むほど増え、検査の意味が薄まる** |

Problem 2 と 3 は同じ形です。**1 言語目の設計を「実装」としては移したが、「なぜそうしたか」まで移していません。** ADR-007 がモジュール分割で解いていた問題を、なでしこ3 版は抱えたままでした。

## Try（次に試すこと）

| # | Try | 期待効果 | 期限・契機 |
| :--- | :--- | :--- | :--- |
| 1 | **段階ごとのコードをどう残すか決める**（Problem 2・5） | ignore が増え続けるのを止める。選択肢は 3 つ（段階ごとのディレクトリ / 検査に「章時点」の概念を入れる / ignore を許容して上限を決める） | Unit 4 の冒頭。ADR に記録する |
| 2 | **Kotlin 版の ADR を 1 件ずつ見て、なでしこ3 版で対応が要るか確かめる**（Problem 2） | 移植しそこねた設計判断を洗い出す。ADR-007 のような「構造で解いていた問題」を見つける | Unit 4 |
| 3 | **検査を書く・直すときに「対象が増えても漏れないか」を完了判定に入れる**（Problem 3） | 3 Unit 連続の同じ失敗を止める。Unit 1・2 の Try は「言語が増えたら」「新しく書くときに」だったが、**ファイルが増えたとき**を含んでいなかった | Unit 4 以降ずっと |
| 4 | **性質テストは試行回数と検出率をセットで記録する**（Keep 1 の定着） | 「green だった」ではなく「壊したら N / M で落ちた」を残す。第 7 章のファンクタ則でも同じ形を使う | Unit 4 |
