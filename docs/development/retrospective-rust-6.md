## Problem（問題）

| # | Problem | 何が起きたか | 原因 |
| :--- | :--- | :--- | :--- |
| 1 | **CI のジョブ間でステップを動かし、道具を入れ忘れた** | `cov` を `db` ジョブへ移したが、`cargo-llvm-cov` のインストールを移さず CI が落ちた | **`parity` 検査は cargo コマンドの一致しか見ない。** ジョブの setup が欠けても止まらない |
| 2 | **計画の具体例が、経路によって作れなかった** | 「利用者名が空 かつ 41 文字」は HTTP 経路で作れない（パスから来るので空にできない） | **実物で書いたが、「すべての経路で作れるか」を見ていない** |
| 3 | **既製品を入れても既定が安全でなかった** | `tera` の自動エスケープが効かず、`<script>` がそのまま出た | 入れた時点で「安全になった」と思い込んだ。**設定を確かめていない** |
| 4 | **測り始めの値を定常と取り違えかけた** | 段階 5 つめの直後、2〜3 回目が 21.23 / 17.68 秒だった | **Unit 3 と同じ形。** 5 回測って気づいたが、3 回で止めていたら「超えた」と書いていた |
| 5 | カバレッジが落ちた | `db` フィーチャの裏が未到達として積み上がり 89.67% | **段階を切るたびに起きる構造。** 第 9 章の `src/bin/` と同じ形 |

**Problem 1 が一番重い**です。**Unit 5 の持ち込み 7（`parity` 検査の対象を広げるか）が現実になりました。** 送ったまま判断していません。

Problem 2 と 3 は同じ形です。**「書いた／入れた」で止まり、「効いているか」を確かめていません。**
